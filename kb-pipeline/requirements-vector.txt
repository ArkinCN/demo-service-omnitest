# 为什么要单独一个文件而不是并进后端的 requirements.txt：
#   后端 requirements.txt 是**客户原依赖逐字锁定**（阶段 1 红线），
#   且 3-K 记录过一次真实事故：直接往后端环境装 docling，把
#   pydantic 2.5.0→2.13.5、httpx 0.26.0→0.28.1 **静默顶掉**，
#   而这两项是后端能跑起来的前提。
#   lancedb 依赖 pyarrow + pydantic>=2.7.4，装进后端同样会顶掉 pydantic 2.5.0。
#
# 装法（在 kb-pipeline 目录下）：
#   .venv/Scripts/python.exe -m pip install -r requirements-vector.txt \
#       --retries 10 --timeout 120
#
# 后端调用方式是**子进程**（同 docling 那条路），见 backend/app/services/
# kb_embed_service.py 与 kb-pipeline/scripts/_vector_worker.py。
