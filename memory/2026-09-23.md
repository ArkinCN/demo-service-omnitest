## 修复：跨轮 id 撞号（用户报「回复重新发一遍」）

### 根因
`c/backend/app/api/v1/agent_stream.py` 的 `_Compat` **每轮请求新建实例**，而 `messageId` 按轮内序号生成（`m-1`、`m-2`…）→ **每轮都从 m-1 开始**。
前端按 `messageId` 严格匹配气泡（`AgentChat.tsx:135`），id 相同即**向旧气泡追加** → 新一轮回答拼进了上一轮的 `m-1` 气泡。

`callId` 同病：两轮给出相同 `call_id` 时，`tool_result` 回填进旧工具卡。

### 修复（仅 backend 一个文件）
- `_Compat.__init__` 加 `run_token`；`_next_msg_id()` 输出 `{run_token}-m{n}`。
- 端点传请求级 token：`r{int(time.time()*1000) % 10_000_000}`。
- `tool_call` / `tool_result` 的 `callId` **同步加同一前缀**（两处必须一致，否则 `tool_start` 取不到、`durationMs` 归零）。
- **前端不用改**（`findIndex` 严格匹配本身正确，错在 id 生成）。
- lint 零错误。

### 教训（永久记住）
**凡是「前端按 id 找节点去改」的协议，id 必须跨请求唯一，不能只用轮内序号。** 适配器实例每轮新建时尤其容易踩。`messageId` / `callId` 都要带请求级前缀，且成对（call + result）必须用同一前缀。

## 4-N 补修四：拉高上限与右列高度（2026-09-23）

- `MAX_ASSISTANT_RATIO` 0.92 → **0.97**

### 永久记住的布局经验
- **grid 行 `minmax` 的上下限要对称设计**：只让一侧能被压扁，另一侧就永远拉不到顶。
- **flex 消息区在内容少时占满剩余空间而显空**，是正常撑开行为，不是布局 bug——不要为它加 `justify-content` 之类把输入框顶上去的补丁。

### 4-N 补修五：助手底部被挤出视口（已修）
- **现象**：助手底部「模型 / 权限」行只露一半，被窗口裁掉。
- **根因**：补修四为消底部空白，同时加了 **`h-full` + `flex-1`** —— 两者打架，父级高度不确定时整块撑出视口。

1. **`flex-1` 与 `h-full` 不要同时用**在同一元素。flex 布局里要填满剩余高度，**只写 `flex-1 min-h-0`** 即可。
