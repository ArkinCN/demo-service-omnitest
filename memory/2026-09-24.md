## 单元 7：助手回答 Markdown 渲染 ✅（3-P）

### 问题
`AgentChat.tsx` 把 `{it.text}` 直接塞进 `.ac-bubble`（还是 `white-space: pre-wrap`），
**全程无 Markdown 解析** → 用户看到 `## 第一段`、`**rated_speed**` 的原始符号。

### 方案：自写轻量渲染器（**不引第三方库**）
理由：依赖是**客户锁定清单**（阶段 1 红线）→ 不为渲染几行聊天文本引 remark/marked 依赖链；
且这类库默认允许原始 HTML，要多做一遍消毒。
- 新增 `agent-chat/components/Markdown.tsx`：块级（标题/列表/分隔线/段落）+ 行内（粗体/行内代码）。
- `AgentChat.tsx` 助手气泡用 `<Markdown>`；**用户消息不渲染**（人打的字原样看）。
- CSS：助手气泡 `white-space: normal`（否则结构间空白被当可视空白）。

### 安全口径（重要）
**不生成 HTML、不用 `dangerouslySetInnerHTML`**，全部走 React 文本节点（天然转义）；
**刻意不解析链接/图片**——助手可能从检索资料带回 url，渲染成可点链接=把外跳口子开进聊天框。

### ⚠️ 快检第一次跑就抓到真 bug（教训）
首版解析器**每个列表行都新建一个块** → 3 条列表项渲染成 3 个各自带符号的 `<ul>`，
行距缩进全乱。快检输出 `blocks: h,p,ul,ul,ul,ol,ol,...` 立刻暴露；改成「上一块同类就续上」
后变 `h,p,ul,ol,hr,p`。
→ **构建通过 ≠ 排版正确**。这类纯逻辑缺陷只有快检能抓，不能靠 `npm run build` 绿就交。

## 单元 12：知识库右栏标题竖排 + id 徽标溢出 ✅（3-T，纯代码已验证）

### 问题（用户两张截图，分两轮报）
1. 「条目详情」四个字**竖排成一列**，顶破定高 44px 栏头，与图标、id 徽标**叠在一起**。
2. 超长条目 id（`motor.cooling-fan.fortior-fu6832:DOC-CASE-0…`）**画出面板圆角边框外**。

### 根因（两处，**都在公共组件，不在知识库页**）
1. **`PanelHeader` 的标题没有禁止收缩**（`components/ui/Card.tsx`）：
   该 `flex` 行里图标 `shrink-0`、右侧位 `shrink-0`，**唯标题 `<h2>` 无 `shrink-0`/`nowrap`**
   → 栏宽不够时**收缩量全压到标题**。中文无词边界 → 不是折两行而是**逐字竖排**；
   `<h2>` 撑到四行高 → 溢出 44px → 与图标、徽标叠住。
2. **徽标与右侧位都 `shrink-0` 且无人裁剪**（`Badge.tsx` + `Card.tsx`）：
   两者都不收缩、也不裁剪 → 超长 id **只能溢出到框外**。

### 修复（3 处，全站受益）
- `PanelHeader`：标题加 `shrink-0 whitespace-nowrap`；`meta` 补 `min-w-0 truncate`；
  **右侧位由 `shrink-0` 改 `min-w-0`（可收缩）**，把省略决策权交回徽标自己。
- `Badge`：改可收缩 + 裁剪（`shrink min-w-0 max-w-full overflow-hidden`），
  正文包 `min-w-0 flex-1 truncate`；**`title` 缺省取 children 字符串 → 悬停出全称**；
  调用方显式传 `title` 时优先（不覆盖 `flow-report` 的 `syntheticBanner`）。
- 正文用 **`flex-1` 而非定宽**：`EntryRow` 有 `w-[76px] justify-center` 的定宽居中徽标，
  正文须是可伸缩项才能真正居中。

### ⚠️ 两条通用教训（永久记住）
1. **flex 行里「中文短标题」必须 `shrink-0` + `whitespace-nowrap`**：
   中文无词边界，被压缩时**逐字断行成竖排**（英文只在空格断，症状完全不同，容易误判）。
   定长标题永不参与收缩，收缩量应交给可变长度内容。
2. **`min-w-0` 是 `truncate` 生效的前提**：flex 子项默认 `min-width:auto`，

## 单元 24：「占位」口径修正 ✅（4-AA）

用户问：「怎么我已经修改并锁定了占位还是 0 没有变成 1」。

### ⚠️ 助手答错了一处（重要，别顺着它排查）
助手说「当前权限是 readonly，所以你的修改不会提交」——**不成立**。
- `permission` 是**助手对话的权限档位**（`copilot/index.tsx:129`），
  只约束**AI 能调什么工具**；
- 用户在页面手动改参数走 `setParam`（直接写 store），**不经过任何权限检查**。
- **模型看到上下文里有 `readonly` 就把它与「改不动」凑成因果**——
  典型「把无关字段当解释」。以后上下文里给了某个字段，要**说清它的作用域**。

### 真根因：「占位 N」是**静态常量**
```ts
const holes = attrs.filter((a) => a._placeholder).length   // 数场景包里 _placeholder 有几条
```
它**不随人操作改变**。人填了值（`overrides` 有值了），`a._placeholder` 仍是 `true`
→ 数字纹丝不动。**这是 4-Z 留下的语义混乱**：让占位字段可编辑了，
却没机制把它从「占位」变成「已确认」。

### 用户拍板的三个口径
1. **数字按「人是否填过值」算**：填过的从计数里减掉；全填完徽标消失。
2. **措辞「占位」→「待现场确认」**（与 tooltip 用词统一）。
3. 「已补 N」进度可见（让人看到自己的进度，不只是一个待办数）。

### 实现要点
- `holes` = 占位项中 `touched` 里**没有**该键的条数。
- ⚠️ **必须订阅 `touched` 而不是 `getState()` 读一次**——徽标要随填值**实时减少**；
  只读一次则 store 变了组件不重渲染，数字还是旧的（正是「数字不动」的同类成因）。
- 判据行：填过显示「**已确认**：源材料没给这一项，当前值由现场填写」；
  未填才显示「待现场确认」。小圆点只给未填项。
- `touched` 是 **`Record<string, true>`（普通对象）**，判存在用 `obj[key]`，
  **不能写 `.has()`**（写错会报 `Type 'Boolean' has no call signatures`）。

### 验收脚本三个新坑
① 假设「初始一定有 N 项待确认」→ 用户已全填过，初始就是 0，
  「填值后减少」观察不到 → **按当前真实状态选方向**（有未填就填、全填就撤标记）；
② 用 `fill('')` 清空输入框做反向测试**无效**——按设计**清空刻意不写 store**
  （0 是有意义的真实值，不能拿空串冒充）→ 改为直接改 store 模拟「未填」；
