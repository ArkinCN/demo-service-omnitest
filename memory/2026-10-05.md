## ✅ 「填了还说缺」根因修复：助手上下文 missing 按「当前实际值」判断（2026-10-05 第二轮）

## ✅ 「填了还说缺」真根因修复：场景包占位用「未知」串不是 null（2026-10-05 第五轮）

用户二次反馈同一问题（截图：左栏«风扇外形尺寸 1mm / 风扇厚度 1mm»已填，助手仍列「数据缺失 5 个点位」）。

### ⚠️⚠️ 真根因（上次修得不彻底）
场景包对「源材料没给的项」**不是写 `null`，而是写 `value: "未知"` + `_placeholder: true`**（实测 `c/data/scenes/*/product-attributes.json` 的 fan_outer_size/fan_thickness）。上次 `isBlank(currentAttrValue())` 只识别 null/undefined/空串 → 对「未知」串失效，**两头错**：
- 人**没填** → 回落到「未知」（非空）→ 误判「已填」→ **漏报**（本次探针实测：修前 missing/placeholders 都是 **0**，尽管包里 5 个占位）；
- 人**填了** → 回落被 override 的数字 → 正确。
上一版实际效果：无论填没填都判「已填」→ 列表恒空 → 用户看到的「5 个点位」其实是**旧会话遗留**，但漏报 bug 真实存在。

### 修法（前端 1 文件，单一数据源）
`web/src/features/copilot/context.ts`：删 `currentAttrValue`，新增 **`isAttrFilled(input, a)`**——**看回落链上「人工覆盖 / 已落盘快照」这一档有没有值**：有且非空=已填；只有源材料的「未知」一律算没填（占位项）/ 按源值判空（非占位项）。`missing` / `placeholders` 都改用它。

### 关键事实（永久）
- 场景包**占位机制**：`_placeholder: true` + `value: "未知"`（不是 null）。凡「判断该字段填没填」的逻辑，**不能只看字面值**，必须走「人工覆盖/快照优先，源值兜底」。
- 后端摘要 `agent_context.py` **只读 envelope 的 zoneB.missing/placeholders**（前端算好的），无独立读包逻辑 → **改前端一处即可，后端不用动**（单一数据源）。
- `__heldEnv` 探针在 init 页读到的可能是**上一页遗留**，且 `window.__useAppStore` 需 Shell 挂载后才在（`waitForFunction` 等）；直接用 `buildEnvelope` 单元验证更可靠。

### 验证（真跑）
- 单元探针 `web/scripts/_verify_envelope_filled.mjs`（新增，浏览器内 import buildEnvelope + getPack）：
  - 未填 → missing/placeholders 各 **5 项**（修复前是 0）；
  - 填风扇两项（overrides）→ 两项消失，剩 3 项；
  - 只填一项（snapshotValues）→ 剩 4 项（快照路径也生效）。
- `npx tsc --noEmit` 退出码 0；read_lints 0 错误。
- ⚠️ 踩坑：JSDoc 注释里写英文双引号 `"未知"` 导致 vite oxc **PARSE_ERROR 页面 500 白屏**——注释里的引号一律用中文引号 `「」`，别用英文 `""`。

### 教训（永久）
1. **场景包占位值 = 「未知」串 + `_placeholder`，不是 null**：这是本次复发真根因，务必记牢。
2. **注释里禁用英文双引号**（vite oxc 会把 `"..."` 当字符串边界，注释也不行？实测它挂在 `201:25`）→ 统一用中文引号。

## ✅ 助手「不按真实情况回答」根治（2026-10-05 第六轮，32+14+13+5 全 PASS）

### 4 条真缺陷（前 2 条是主因，与第五轮的结论**不同**，第五轮诊断不完整）
1. **开场那一问发出时上下文包未就绪**：`AgentChat` 的 autoStart effect 与 `ActionDock` 的 `setHeldEnv` effect 在同一次 commit；`dshAdapter` 取不到 `heldEnv()` 就**整段不送 context** → 模型凭通用知识列「常见占位项」。**根治靠显式门闩，不能赌 effect 顺序。**
2. **占位项「填没填」判据用错轴**：场景包 5 个占位项里 **3 个带推定值**（rated_speed 按 MOTOR_MAX_SPEED 暂取、rated_voltage 按归档工作流 12.5V 推定、rated_current 按 I_Value 暂取），只有 `fan_outer_size`/`fan_thickness` 写「未知」。按「有没有值」判 → 推定值被当成「人已填」。
3. **`missing` 与 `placeholders` 判据不同轴 → 同一字段两处都报**（实测「风扇外形尺寸」同时在 missing 和 filled）。
4. **缺值段只看本体属性 29 项**，控制参数 70 + 报告表头 10 缺席。

### 关键事实（永久）
- **「人填没填」的唯一判据 = `touched`**。`overrides` 会被 `applySnapshot`（`flow-init/snapshotApi.ts:415-420`）用**历史快照整份回填**污染；`snapshotValues` 是落盘基线 → 两者都不是「本次填写动作」。**实测：该浏览器 profile 有 13 条 touched / 115 条 overrides，差值就是历史快照。**

## ✅ 智能测试：无论成败都自动下载报告（2026-10-05 第九轮，16/16 + 21/21 全 PASS）

用户：截图显示流程3失败后结果卡只有「重试/关闭」，**拿不到任何报告**。要求「无论导出成功还是失败都必须自动触发报告下载，复用后端已有导出逻辑」。

### 根因（1 条）
`automationOrchestrator.ts` 的「流程5 报告生成 + 下载」整段包在 `if (finalStatus === 'completed' && !stopRequested)` 里 → 流程3一失败就**整段跳过**，report 阶段永远 `pending`。附带问题：生成与下载被拆成**两次 `runStage(byId('report'))`**（同阶段跑两遍，日志两条）。

### 修法（**后端零改动**，纯复用）
- 报告段去掉 `completed` 前置，改 `if (!stopRequested)`；**生成与下载合并成一次 runStage**（先生成，`blocked` 时抛出如实标 failed 不下载，再下载）。
- 报告阶段成败**不回写 `finalStatus`**（测试失败 ≠ 报告失败）。
- `report` 阶段显式 `minShowMs: 300`（不沿用默认 900，失败路径多等没意义）。
- `AutomationSummary` 扩 `reportStatus/reportFile/reportReason`；`generateReport` 适配器**透传后端三档**（ok/placeholder/blocked + reason/file）。
- `downloadReport` **先 HEAD 探存在性**（复用 `reportExists`）再点 `<a>`——避免 404 白屏页被当成「功能坏了」。
- 结果卡**报告行由「仅 completed」改为三态都显示**，失败态注明「报告为失败快照」并给「查看报告」入口。

### 关键事实（永久）
- **后端三档契约早就就绪**：`POST /api/reports/generate` 返回 `ok | placeholder | blocked`（各自带 `reason`/`note`/`file`）；**模板缺失时生成占位 xlsm（真文件可下载）**；`GET /api/reports/{id}/download` 兜底 `.xlsm → .placeholder.xlsm → .placeholder.json`，全无则 404 并说明怎么办。
- **失败场景可行的前提**：`build_placeholder_workbook` 入参全为已装配真题数据，**缺的写「由上游带入（未提供）」，`verdict=None` 时跳过判定汇总** → 只有 config-snapshot、无判定表也能出报告。流程1/2 已真落库并 `setRunId`，所以流程3失败时**轮次存在**。
- **无轮次场景**（流程1就失败）：`resolveReportRunId` 抛「本场景还没有落过轮次」→ 如实记 `blocked`，**不补建空轮次、不假装下载成功**。

### 效果（同一失败场景）
修复前 `stages=[init:success,req:success,run:failed,tune:pending,report:pending]`，结果卡无报告入口；
修复后 `stages=[...,report:success]`、`reportStatus=placeholder`，结果卡：「报告已生成（系统自建模板，可替换）… **· 本轮测试未全部通过，报告为失败快照（缺的项如实标注「未提供」）**」+「重新下载 / 查看报告 / 重试 / 关闭」。

### 教训（永久）
1. **「报告要等测试跑完才出」是错的假设**——判据应是「有没有可写的轮次数据」，不是「测试是否通过」。失败报告反而是最有用的。
2. **复用后端能力的正确姿势是先读它的三档契约**：`status` 不是装饰，是给调用方分流用的。只把 `blocked` 当失败、其余全算成功 → 会把占位件说成交付件。
3. **「下载」前先确认「文件存在」**：直接点 `<a href>` 遇 404，浏览器给白屏/报错页，人读成「功能坏了」而非「报告没生成」。
4. **阶段最小展示时长的断言要跟着豁免规则走**：`run` 阶段 `minShowMs=0`，所以 `run→report:67ms` 是正常行为；断言把「刻意不延迟」误判成「闪切」→ 假 FAIL。
5. **TS 控制流分析看不到闭包内赋值**：`let x = 'skipped'` 后在 `runStage` 回调里赋值，TS 一直窄化成 `'skipped'`，后续比较全报「类型无重叠」。**在声明处显式标注完整联合类型**即可。异步编排代码里很常见。
