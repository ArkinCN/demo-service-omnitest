## 「助手不回答」根因定位与修复（2026-09-22）

### 根因：前端三处吞错，不是后端问题
curl 已证后端全通（返回完整回答 + done{complete}）。问题在前端**把失败静默吞掉**：

| # | 位置 | 缺口 |
|---|---|---|
| 1 | `AgentChat.tsx` `run()` | 只有 finally，**没有 catch** → 异常被吞，界面毫无反应 |
| 2 | `AgentChat.tsx` `apply()` done 分支 | **丢弃 `ev.message`** → `done{reason:error}` 时错误不可见 |
| 3 | `api.ts` `dshAdapter.send` | **fetch 未包 try/catch** → 代理/连接失败时异常上抛，落进第 1 处的黑洞 |

### 已做的修复（3 处，仅前端）
1. `AgentChat.tsx`：`run()` 加 catch（非中止时落成可见错误气泡）；`apply()` 的 done 分支在 `reason==='error'` 时追加助手消息显示 `ev.message`。
2. `api.ts`：`dshAdapter` 的 fetch 包 try/catch（中止→aborted，其余→error + 「请求未送达：…」）。
3. 契约补全：`AgentChatProps` 新增可选 `sessionId` 并透传；`copilot/index.tsx` 传 `shell-<sceneId>-<flow>`（与 context.ts 同口径）。背景：**全工程此前无任何地方传 sessionId**，`session_id` 恒 undefined（本阶段后端 history=null，不影响回答，补齐为契约完整）。

### 状态
lint 零错误；**build 未跑**（execute_command 审批超时被取消，未获执行）。待用户重启 vite 后复验。

### 教训（永久记住）
- 前端「发消息无反应」= 优先查 **catch 缺失**与 **done{error} 的 message 是否被显示**，不要先怀疑后端。
- **execute_command 审批可能超时被取消**（非用户拒绝）；此时不要反复重试，改用只读工具复核 + 交用户执行。
