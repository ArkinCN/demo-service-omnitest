# _图 · 通用 Agent 测试系统 v2.0 配图说明

七张手排 SVG（fig2 有改版前后两版，正文只用第三轮改版后的一版），供飞书文档「设计规格-信息架构与页面」与「业务逻辑说明-六个流程」插图用。每图一份 `.svg`（矢量源）与一份 `.png`（cairosvg，scale=2，即两倍分辨率位图）。生成脚本为本目录下的 `_gen.py`，改坐标后重跑即可全量重出。

配色按项目硬约束：描边墨绿 `#2E5E45`、次级 `#A8C5B5`、文字 `#2C2C2C / #555555 / #9A9A9A`、分隔线 `#C8C5BD`、淡底 `#EAF2EC`、深绿实底 `#1F4232`（全套仅 fig5 用一处）、强调暗红 `#A6353A`（每图不超过两处）。无第三色相、无渐变、块不做实色填充、嵌套不超过两层、连线不交叉。

## 二、与原 mermaid 图的差异（全部为有意简化或合并）

本目录不使用 mermaid 自动排版。以下逐图说明手排版本相对源文件内 mermaid 的增删。源文件指同一目录上一层的 `01-设计规格-信息架构与页面.md`、`02-业务逻辑说明-六个流程.md`、`00-用户需求原话-20260919.md`。

**fig1** 依据 `01` 第 2.1 节的分区 mermaid。原 mermaid 只表达四块的嵌套关系，本图改按第 2.2 节栅格表的真实数值排版（A 通栏 140 高、B 宽 384、C 高 496、D 高 328），并把第 4 节全局层级树里各块的 ① 到 ④ 层级压进对应块内；顶部六个流程标签、四个动作按钮来自第 5.2、5.3 节的表格，原 mermaid 中没有。

**fig2**（`fig2_五流程主线与知识库层带`，第三轮改版）依据 `06-第三轮需求变更方案-v0.1.md` 第 1.2 节的分层图草案重排：知识库不再占流程序号，主线收为五步并按 1–5 重排编号；知识库画成承托在主线之下的层带，层内按 1.3 节给出归属、来源、用途三轴与五段转化流水线；主线与层带之间只留「取（填参数 / 抽判据 / 套模板）」与「回（沉淀经验 / 归档报告）」上下两组箭头，不再逐流程拉双向细线。旧版 `fig2_六流程主线` 的说明如下，保留备查：依据 `02` 第二节的主线 mermaid。新增每框的「入 / 出」两行，取自 `01` 第 9.1 至 9.6 节各自的输入与输出条目。原 mermaid 里「安全联锁就绪」只是一条边上的文字，本图把它画成 ③ 与 ④ 之间的闸门符号，判定内容取自第 9.4.3 节的闸门 mermaid。**已简化**：未画 `01` 第 10 节状态流转图里的另外两条回退路径（③ 回 ②、⑤ 回 ③），只保留 ⑤ 与 ④ 的主闭环，两条回退路径在正文表格中有完整说明。

**fig3** 合并两张 mermaid：`01` 第 9.1.2 节的三级分类树与 `02` 第 5.1 节的知识库结构图。**已改动**：八个文档类型不再平铺成一排，按对象类、规则类、产出类三组收敛；三级树的示例按需求方给的口径改为「电机 › 家电电机 › 散热风扇」与「汽车 › 车身电机 › 雨刮电机（占位）」，原 mermaid 里汽车分支写的是「整车（占位）› 待补」。底部的增删改查工具带是第 9.1.5、9.1.7 节动作按钮的归并，原 mermaid 中没有。

**fig4** 依据 `01` 第 11.1 节的场景包 mermaid 与 `02` 第 5.2 节。**已改动**：原 mermaid 是一棵九分支的星形，本图改成「系统侧 / 通用结构 / 两个实例」的三列对照表，因为「换场景只换包」这件事靠两列并排比靠星形更直观。⑤ 工作流模板库下补了四类节点（设置、激励、采集、判定），来自第 9.3.2 节。左右两列的实例内容取自各流程的「峰岹散热风扇案例」行。**与任务清单的一处出入**：任务给的场景包清单是八项，本图按 `01` 第 11.1 节画九项，多出的一项是「⑨ 界面配置」。

**fig5** `01` 与 `02` 中没有对应的 mermaid，本图为新作。内容合成自三处：第 7.4 节单机设备的四种接入方式表、第 12 节前端实现建议表、`00` 需求原话里「系统基于浏览器，不能基于单机」与「示波器这类必须单机的，SSH 过去」。服务端的两块构成（FastAPI 应用服务与 DeepSeek Harness 运行时）按本轮任务给定的口径画。第 7.4 节原表列的是四种形态的适用与实现要点，本图把它们转成四种线型。

**fig6** 依据 `01` 第 8.3 节的副驾职责边界表与第 13 节第 8 条决定。**已改动**：原文只有「副驾做什么 / 绝不自动做」两栏，本图把两栏各自再按行为性质分组（左四类、右三类）。**一处命名需注意**：「权限三档」不是原文里的现成术语，是本图对第 8.3 节统一规则与第 9.4.3 节安全确认闸门的归纳，划分依据是「会不会落盘」与「会不会动被测对象」两道线。若这个提法需要进正文，要先在 `01` 里补定义。

## 三、复检记录

各图均以 cairosvg scale=2 渲成 PNG 后逐张人眼复检，检查项为文字重叠、文字溢出框外、连线交叉、块越界。生成脚本内置文本宽度估算，凡文本超出所在框宽即报警，最终一版零告警。首轮发现并已修正三处：fig1 工具条底部的层级注记与上方组名过挤（改为并入工具条抬头）、fig2 知识库轨道说明文字左侧出画（改为左对齐并上移轨道）、fig2 中「⇄」字符在 Microsoft YaHei 下渲成方框（改为「与…双向」的文字表述）。

第三轮改版新增的 `fig2_五流程主线与知识库层带` 单独复检一次：脚本文本宽度估算零告警，PNG 上核对了五个流程框的标题与「入 / 出」两行无溢出、闸门标注落在 2 与 3 之间的空档内不压框、4 回 3 的虚线折回走框上方不与主链相交、「取 / 回」两条箭头落在主线与层带之间的空档内、三轴淡底块与转化流水线五个节点无重叠。淡底（`#EAF2EC`）只用在三轴块，占画面约 10%，暗红只用在安全联锁闸门一处。
