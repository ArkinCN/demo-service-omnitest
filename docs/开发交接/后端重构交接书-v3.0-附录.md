### 通用接口规则（所有新接口共同遵守）

- **用户身份从登录会话取得**，不能相信请求里的 `operator`、角色或权限。
- **POST 创建和设备动作带 `Idempotency-Key`。** 服务端按用户、任务、接口和键存请求摘要；相同请求返回同一结果，**不再执行**；同键不同内容返回 `409`。**记录不能仅放进进程内存。**
- **修改已有资源带 `expected_version`。** 版本不符返回 `409` 并返回当前版本；**冻结后的配置和基线只允许派生新版本**。删除被运行引用的对象返回 `409`。
- **通用错误形如** `{"error":{"code":"VERSION_CONFLICT","message":"配置已被其他人修改","retryable":false},"request_id":"…"}`。`400` 输入错误；`401` 未登录；`403` 无权；`404` 不存在；`409` 状态或版本冲突；`422` 业务条件未满足；`429` 限流；`503` 依赖不可用。**不能用 HTTP 200 包一个失败结果后让前端继续成功流程。**
- **列表用 `cursor/limit`**；**文件用不透明 ID**，服务端校验所属任务、类型、大小和摘要。**客户端不能传服务器任意路径。**
- **日志记录 `request_id`、用户和对象 ID，删除 PIN、密钥及模型凭据。**

### 四条硬约束

**① 依赖锁定不许动。** 顶层唯一依赖是 `@deepseek-ai/dsh@0.1.5-rc.2`，**精确版本不带插入符号或波浪号**。**严禁在顶层单独安装任何 DSH 子插件包**，它们已内嵌在主包自己的依赖目录里。

| 类型 | `rule` | `confirm_required` |

## C.6 · 换场景不变性的验证

**一句话验证法**：两个场景对比下来，`id`、`label`、`type`、`touches_redline`、`degraded_to`、`context_requires` **全部相同**，变的只有 `source`、`skill_ref`、`prompt`、`operation` 四个字段。

### 三层切分

| 层 | 内容 | 换场景时 |
| -- | -- | -- |
| **结构层** | 上下文包的九段结构（+ `envelope_version` 与可空 `action`）、按钮的字段定义、三类按钮的语义、红线降级规则 | **不变** |
| **编排层** | 每个流程有哪几枚按钮、按钮 id、图标、类型 | **不变** |
| **内容层** | 预置 prompt 里的业务名词、`skill_ref` 指向的规程、`operation` 的工具名 | **换** |

### 逐字段对照（举两例）

| 字段 | 电机场景 | 升降器场景 |
| -- | -- | -- |
| `id` | `run.precheck` | `run.precheck`（同） |
| `label` | 预检自检 | 预检自检（同） |
| `type` | execute | execute（同） |
| **`source` / `skill_ref`** | **customer** / `hw-selfcheck-vbus` 等四份 | **ours** / `window-precheck`（客户规程不覆盖汽车场景） |
| **prompt 里查什么** | 供电、功率输出级、采样链路、四路通道信号 | 供电、H 桥驱动、霍尔锁存脉冲链路、位置计数零点、行程限位 |
| `context_requires` | `/zoneC/devices` | `/zoneC/devices`（同） |

### 一条数据诚实性的约束

**升降器场景的执行类按钮第一版不开放**——没有真设备可连。该场景的**解释类与准备类按钮的 prompt 必须额外带一句「引用数值时标明来源状态」**（该包时序数据是合成的、判据数值来自征求意见稿）。

| **采样率** | — | 仪器每秒钟测多少个点 |
| **深存储** | — | 示波器把很长一段波形按原始分辨率完整存下来。**做异常分析时必须用它** |

| 词 | 人话解释 |

### 流程与判定

| 词 | 人话解释 |
| -- | -- |
| **判据** | 一条「怎样算合格」的规则。格式是：指标 + 方向 + 阈值 + 容差 |
| **阈值 / 容差** | 阈值是那条线；容差是允许偏离的范围 |
| **需求基线** | 开测之前冻结下来的那份「判据 + 工作流 + 案例清单」 |
| **工作流** | 一条测试流程，由一串步骤组成，画出来是一张有向图 |
| **规程** | 一份写清楚「这类测试该怎么做、哪些线不能碰」的操作说明 |
| **回归 / 长跑** | 把同一件事重复很多次，看成功率 |
| **启停测试** | 反复启动停止，统计每次是否成功、用了多长时间 |
| **顺风重启 / 逆风启动** | 风扇已经在转的时候再让它启动 |
| **安全联锁** | 一组「不满足就绝对不许启动」的前提条件 |
| **场景包** | 让系统适配某个产品类型所需的全套配置资产 |
| **轮次产物** | 跑一轮测试产生的全部东西打成的包 |

| **四道约束** | 单次使用 / 180 秒过期 / 绑工具名 / 绑参数指纹 |

## D.3 · 已定决策（不要重新选型）

| 决策 | 理由 |

| **主界面固定四块**，每块内部最深到四级，第五级必须换弹层、抽屉或独立页 | 防止元素堆在一个块里 |

| **报告模板填充复用客户已有的 Rust 工具，不自研 Excel 写入** | 该工具已经处理完「按文件名规则把截图落到正确单元格」与「从 CSV 读转速写进性能表」这两件最麻烦的事 |
