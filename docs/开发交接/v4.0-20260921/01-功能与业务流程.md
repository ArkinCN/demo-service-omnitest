# 功能与业务流程

## 一、这套系统帮助谁完成什么事

测试工程师拿到一台样机，需要明确产品参数和合格标准，连接台架采集数据，判断是否合格。不合格时查原因、改参数再测，最后出报告。系统负责保管资料、组织步骤、采集分析和整理报告；工程师确认依据、批准影响设备或正式文件的操作。

主线固定为：初始化配置 → 测试需求 → 启动测试 → 调优并复测 → 测试报告。测试直接达标可跳过调优。知识库是所有步骤共用的基础模块，随时进入，不占流程序号。

一次“测试任务”绑定样机和场景；一次“轮次”是这项任务的一次执行。同一任务可以有多轮，每轮保存自己使用的配置、判据和参数版本。后来的改动不能改变已结束轮次的结论。

## 二、知识库：先把材料变成可查的依据

### 用户怎么操作

按场景、子类、产品类型选择归属；上传文件，或新建经验。条目同时按来源和用途筛选：来源是文档或经验，用途是产品说明书、测试需求或工艺。文档类型是另一个字段，不能拿它替代用途分类。

初始化页也有上传入口，归属预填为当前产品，与知识库共用一个上传和处理服务。

### 后台怎么处理

1. 保存原件和内容哈希，识别格式、归属和版本；同一原件允许被多个产品引用，不能重复复制成互不关联的条目。
2. 创建处理任务，依次识别、抽取、切片、结构化、建立索引。每一步记录进度、版本和错误。中途失败保留原件，从失败步骤重试。
3. 按八类文档模板抽取：产品描述、驱动固件、功能清单、原理图、标准规范、测试规程、报告模板、历史报告。场景包已有的细分类映射到这八类，保留原分类，不强行抹掉。
4. 每个抽取字段保存原文位置、单位、原值和置信状态。低置信度进入人工校对，不直接成为启动限值或判定标准。
5. 检索返回当前用户可见的条目版本、摘录和定位。未审核经验允许检索但必须标注，不升级为“实测证实”。模型没有命中依据时明确说明缺材料。

### 修改和删除

修改产生新版本，经验修改必须填写理由。旧引用保持指向旧版；新版本出现时提示“依据有更新”，不自动重算历史结果。删除是软删除，默认保留 90 天；有引用时拒绝删除并返回引用方，可改为停用。到期清理仍须检查引用和保留策略。

### 做到什么才算完成

上传一份测试文档后，用户能看见处理状态、校对抽取值、检索到原文，并从配置字段跳回对应文档版本和位置。模拟解析失败、重复上传、删除被引用条目时，都有可操作的说明。

当前已有离线处理脚本和静态产物；在线上传、后台队列、版本化和权限接口需要开发。

## 三、流程 1：初始化配置

### 要回答的问题

测的是哪台样机，用哪个固件和台架，哪些条件不满足就不能启动。

| 配置类 | 用户核对什么 | 服务端保存什么 |
| --- | --- | --- |
| 被测对象 | 型号、样机编号、本体属性 | 身份、带单位的属性、来源和人工修改记录 |
| 驱动与控制 | 工程、固件、可调参数清单 | 文件标识和哈希、版本、参数白名单、编译烧录适配器 |
| 台架与仪器 | 设备、接线、量程、校准 | 设备标识、信号映射和校准状态，凭据仅存服务端 |
| 安全联锁 | 人员确认、电气限值、流程条件 | 独立联锁实例、检查方式、有效期、触发动作 |
| 运行与产出登记 | 任务名、操作者、交付对象 | 任务元信息及报告表头默认值 |

文档预填先产生草稿；用户接受后保存。手动修改记录原值、新值、修改人和来源变化。数值校验包含类型、单位、范围和步长；资料没有给的值保持缺失，不能用演示值补齐。

“校验配置”返回逐字段错误和警告。“提交并锁定”必须由服务端再次校验，生成不可变的配置快照。后续变更复制为新草稿，再产生新快照；已运行轮次仍引用旧快照。另存参数模板只保存可复用配置，不带样机身份和现场确认结果。

基线备份是实际文件复制与哈希核验，要有人批准。备份失败、文件不可读、哈希不匹配均不能把“原始备份已保存”联锁置绿。

当前页面锁定只改浏览器状态；文件预填、配置校验、模板保存以及服务端锁定需要开发。

### 硬件参数辨识和电机参数辨识放在哪里

这两项是早期对话里明确要求保留的能力，放在初始化配置内，以任务方式启动，助手负责解释和准备。硬件辨识针对控制板和测量链路，例如采样电阻、放大倍数、分压比例和通道映射；电机辨识针对被测电机，例如电阻、电感、极对数和反电动势相关参数。具体可测项目以实际工具支持为准，不能声称都能自动辨识。

读取已有文件得到的值叫“导入值”，根据波形计算的值叫“辨识值”，人工填写的值叫“人工值”。每项保存单位、方法、工况、原始数据和确认状态。需要向设备施加电压或转动电机的辨识是设备动作，必须预检、联锁和人工批准；不能因按钮叫“辨识”就当只读操作。辨识失败或结果不可信时保留原值，提示复测或人工确认。

用户采纳后生成新配置草稿，展示差异，再按正常流程锁定；不直接改当前运行的配置。汽车等无相应辨识能力的场景显示不适用，不调用电机专用工具。

## 四、流程 2：测试需求

### 要回答的问题

本次测哪些项目、什么条件算合格、用什么步骤取得证据。

每条判据包含指标、单位、方向、阈值、容差、等级、采样方式、适用工况和依据版本。阈值未核实的项目可以进入草稿，不能静默成为正式测试标准。

用户导入标准，校对抽取结果；选择工作流模板，编辑本次实例。后台检查每条判据是否能找到对应测量量，测量量是否能由所选设备和步骤提供。缺通道、单位不兼容、未支持节点必须列出位置。

工作流支持设置、激励、采集、判定、控制流、数据处理六类能力，另有循环和子流程。解析未知节点时允许展示，但执行必须拒绝并说明缺哪个适配器。画布可编辑并不等于执行器已经实现。

确认需求基线时保存判据、工作流实例、案例清单、整体判定规则和版本。冻结后修改产生新版本，不能修改正在执行轮次的标准。

当前 `.wfw` 解析与画布可以复用；图执行、真实编辑保存、标准导入和冻结持久化需要开发。

## 五、流程 3：启动测试与结果分析

### 开始之前

必须绑定已冻结的配置和需求基线、当前参数版本、台架、运行设置。运行设置包括重复次数、每次时长、采样方案、失败后的处置和存储策略。

服务端检查三类条件：联锁有效、预检通过、操作员本轮现场确认有效。预检必须查询真实设备能力和状态；页面上的勾选不能代替自动检查。确认过期、设备掉线、配置换版后要重新检查。多人使用同一台架时按租约排队，禁止两个任务同时控制同一台设备。

### 启动以后

用户点启动，确认卡显示设备、参数和物理影响。批准必须绑定这一次动作和这一组参数。后台在实际执行前再次检查权限、联锁和租约，随后调用设备适配器。只有设备接受并回报状态后，页面才能显示正在运行。

运行中推送进度、步骤和测量数据，并持续记录原始数据与日志。正常停止保留已采数据。设备失联或执行超时不得显示“正常结束”；动作是否已经发生不清楚时标记“结果待核对”，禁止自动重发启动或写回。

急停在旧需求中要求立即生效，但当前原型仍走 PIN 确认。这个冲突列为实机上线阻断项；须由设备负责人确定独立停止通道和确认策略，不能把当前弹窗演示当成急停验收。硬件保护触发的自动停机与助手自主发动作是不同机制，保护链路必须独立于模型服务。

### 怎样判定

每条判据至少区分 `pass` 通过、`fail` 不通过、`missing` 缺测量、`manual` 待人工、`error` 求值异常。轮次状态与判定结果分开：设备错误可能导致轮次无效，不等于产品不合格。

缺量不能补零。合取式可以在同一有效轮次已知子句为假的情况下判失败，同时保留缺量列表。历史批次不能混入当前轮次；演示用的 67/98 历史统计必须标明来源，不能因为本轮点过启动就改称本轮结果。整体结果由冻结规则确定，必测项缺失或待人工时不得判整体通过。

输出七份产物中的轮次包、判定表、未达标清单；波形保留原始精度，页面抽稀只影响展示。异常定位返回时间区间、关联通道和原始文件定位。历史比较只比较单位、工况和规则兼容的轮次，不兼容项说明原因。

断点续跑从明确完成的安全边界开始，重新预检和人工批准。故障后不能盲目续执行烧录、写参数或施加激励节点。存储不足提前阻止启动，运行中不足时按批准的降级策略处理并记录丢失范围。

## 六、流程 4：调优与复测

从有效的未达标项进入，保留来源轮次和判据。缺测量项进入“补采集”，不能和调参建议混在一起。

候选分三路：相似经验、已验证规程、模型推断。每条说明现象、建议参数、原值和新值、单位、证据、风险及建议复测项。排序优先考虑证据可靠性，再考虑相关性和可执行性；模型建议始终保留标识。

人选中候选后，后台计算实际改动和影响面，生成 diff 草稿。确认卡、批准票据和设备实际接收到的参数必须完全相同。当前代码写死的 `ALIGN_CURRENT=0.6`、启动占空比和 `demo-run` 必须取消，不能继续用于真实操作。

写参数按场景白名单定位，保留编码、行尾、注释和定点数外壳，不允许整段重写文件。写回前验证原文件哈希，变化则拒绝并重新出差异。需要编译烧录时，顺序为写入、编译、烧录、回读核对；每一步独立记录。编译成功不等于设备已经应用。

回滚产生新的参数版本，按相同批准和核验流程执行。禁止用强制 Git 回退覆盖现场工作。试过的候选和失败原因要记入历史，次数、时长或候选预算耗尽时转人工，不无限循环。

复测创建新轮次，与前一轮关联。只有复测证据支持时，经验才能写成“调整后改善”；原型的历史 PASS 曲线不能充当本次修改有效的证据。经验先形成草稿，人审核保存后入库。

## 七、流程 5：报告与归档

选择任务和轮次，后台按固定模板版本生成报告草稿。填入样机信息、基线版本、判定表和图，结论由结果汇总后生成，不能由模型自行改变通过与否。

每个数值绑定产物标识、原始字段或采样区间；在线预览可跳转来源，离线报告通过引用编号和随包的来源清单追溯。客户 `.xlsm` 的宏、工作表、公式和图片定位要用真实模板回归验证。

缺字段时列出“需要补数据”“需要人工填写”“允许留空”三类；合成数据和待核实阈值只能产生带标记的演示或内部分析报告，不能冒充实测合规结论。

人工复核结论后才允许导出。导出成功必须有真实文件、大小、哈希和可下载地址；页面通知“已导出”不算完成。归档是单独的人工作业，把历史报告和经验关联回知识库，重复归档不产生重复条目。

## 八、所有页面共用的行为

切换产品前提示未保存草稿；运行期间禁止改变本轮绑定的场景和设备。切页不丢已保存数据，刷新能恢复任务状态。未登录、无权限、接口超时、桥离线均有单独提示，不静默回放为成功。回放、模拟、实机模式始终显示且由服务端校验。

画布布局按场景和流程保存，提供恢复默认；默认拓扑从场景配置加载。设备终端只在授权后的放大视图出现，不能成为绕过动作权限的入口。B 区内部滚动和小屏布局须用真实浏览器验收。

语音输入接入后只是生成待发送文字，用户核对后发送，不因识别结果自动启动设备。模型选项由服务端配置的可用模型列表提供，现有页面字符串不代表相应模型已经可调用。
