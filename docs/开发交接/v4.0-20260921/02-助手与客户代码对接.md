# 助手与客户代码对接

## 一、先分清三个工程

| 对象 | 当前事实 | 在新系统里的作用 |
| --- | --- | --- |
| 本仓 `web/` | 页面助手走 `makeAdapter` 脚本回放 | 保留界面和事件卡片，接新的真实会话接口 |
| 本仓 `dsh-plugins/` | DeepSeek Harness 运行时验证，含工具桩、技能和 Hook | 作为真实智能体集成的起点，不当作完成的业务后端 |
| 客户脱敏代码 | 另有 API、桌面端、Rust 调试库、MCP 和报告工具 | 经内部渠道取得后逐模块适配，不整套塞进浏览器 |

客户已有后端不等于新系统后端已经完成。客户调试能力也不集中在 Python API：一部分在桌面前端的流程编排，一部分在 Rust 库和本机工具。新系统基于浏览器，必须给这些能力加设备侧服务和明确的输入输出。

## 二、一条真实请求应怎样走

1. 人在页面提问或点按钮。前端提交消息、按钮标识、任务及轮次标识、页面上下文和请求唯一标识。
2. 会话服务核验登录身份与任务访问权。重新读取服务端的配置、基线和设备状态；浏览器传来的权限、操作者和联锁结果只作展示线索，不能作为授权依据。
3. 根据当前流程和按钮选择已登记的技能。检索任务所属产品及通用资料，返回来源版本和位置。缺关键材料时询问或给缺项，不猜阈值。
4. 运行时调用允许的工具；参数和输出都校验类型。工具不得直接开放任意 shell、任意路径写入或无限设备指令。
5. 文字、依据、工具进度和结果流式返回页面。草稿采用结构化补丁回填字段，服务端保存草稿，不只显示一句“已经填好”。
6. 遇到写文件或设备动作暂停，展示真正的参数供人批准。批准与拒绝都记录；超时、关闭页面、取消会话不得默认批准。

助手只读档允许查询和解释；参数档允许形成及经人批准保存参数改动；硬件档还需台架权限和现场条件。自动执行开关只影响已登记的只读工具，不能绕过人工确认。

## 三、页面上下文与输出

每次请求包含：会话、产品、流程、B 区表单、C 区选中对象、最近轮次、历史引用、知识引用、策略、按钮动作。大文件只传标识和摘要，后端按权限读取，不能把完整波形或全部文档塞进 prompt。

B 区要发送当前完整有效值及修改信息，不能只给 `overrides` 而漏掉未改的默认值。选中文档、未达标项、候选和画布节点必须进入共享状态。来源轮次与页面正在查看的轮次不同，先提示用户，禁止自行替换。

草稿输出建议统一为 `draft_id / target / base_revision / changes / evidence_ids / warnings`。`changes` 每项带字段路径、旧值、新值、单位和来源。前端定位字段并显示差异，人采纳后才进入正式保存动作；版本已变返回冲突，保留草稿供重新核对。

历史摘要只来自已发生的消息，区分“用户说”“工具测到”“模型推断”。中断会话后可恢复消息和工具状态，但不会自动续执行未完成的危险动作。模型超时有错误事件；没有最终 `done` 的断流显示“连接中断”，不显示成功。

## 五、客户代码复用地图

以下路径相对于内部交付的“平台代码-脱敏版”，不在本仓。它们是本次读到的源码入口，未在本轮重新编译或实机执行。

| 模块 | 源码入口 | 可复用内容 | 必须补的适配或核验 |
| --- | --- | --- | --- |
| 账号及模型服务 | `api/app/main.py` 及其路由 | 身份、权限、聊天和额度相关服务组织 | 逐条评估依赖、数据迁移、鉴权；不能把客户账号体系默认当新系统可用 |
| 模型调用 | `debug-agent/src/chat/client.rs`、`session.rs`、`tool.rs` | 流式调用、消息与工具结构 | 和 DSH 选定一条主调用链，避免双循环、重复收费与重复执行 |
| 调试流程 | `debug-agent/src/applications/vacuum/state_machine.rs`、`startup_adjust/executor.rs`、`loop_tune.rs` | 状态机、取消检查、启动调参流程 | 原逻辑面向吸尘器；散热风扇适用性需核实，固定示例结果不能当测量 |
| 参数与固件 | `debug-agent/src/identification/`、`compilation/compile_with_download.rs` | 参数识别、编译下载适配 | 白名单、文件哈希、超时、烧录回读、失败恢复和人工批准 |
| 仪器与设备 | `debug-agent/src/transport/`、`oscilloscope/`，独立 `mcp/`、`rigol_rust/`、`rigol_master/` | 串口/HID/VISA 等设备通信入口 | 锁定设备与驱动版本，逐个验证真实返回、取消和断线行为 |
| 桌面工作流 | `app/src/features/integrated-test-system/workflow/` | `.wfw` 模型与已有执行逻辑 | 浏览器不能直接调用 Tauri；把运行能力放在设备宿主，不能只移植画布 |
| 报告 | `writeFile_rust/src/main.rs` 与 `processor` | 模板图片、CSV 插入 | CLI 的 `variable_data` 当前为 `None`，需补普通字段和结论填充；用宏模板验证不损坏文件 |
| 技能与规则 | 客户安装目录 `resources/data/dc-skills/`、`dc-rules/` | 现场调试规程 | 内部补交正文、版本及场景绑定；逐个对照输入输出后转写 |

设备命令行工具可能仍依赖客户账号、授权、驱动和常驻桌面会话。源码存在不能消除这些依赖。每个复用模块交一张适配记录：版本、入口、输入输出、外部依赖、实跑结果、可替换方案。

## 六、审批链路必须验证的细节

当前桥的 PIN 是第二层鉴权，但 PIN 仍会经过浏览器内存。`approved_by` 当前由页面提供，不能证明实名身份；`human_pin` 说明使用了 PIN 渠道，也不能独立证明真人在场。正式部署要绑定登录账号、操作审计和批准权限，且模型工具环境不得读取批准凭据。

批准、执行、设备回执分成三个状态。桥返回 HTTP 200 可能只是业务拒绝；客户端必须检查 `status` 和 `executed`，还要核对真实设备回执。当前 `flowActions.ts` 在调用返回后直接更新页面，必须修为明确成功后才更新。

审批只出现一次，统一确认卡；真 SSE 路径要核验不会先弹通用确认、再弹 PIN 确认造成重复审批。拒绝、过期、参数变更、服务重启、事件重复都不能造成二次执行。票据持久化要保存审计，但重启后未执行的批准不得自动恢复执行权，重新核对现场再申请。
