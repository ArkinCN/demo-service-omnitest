# 开发任务与缺口清单 v4.0

下面每个编号都是需要开发或核实的工作，不是已完成清单。责任写角色，开工时由负责人填姓名与日期。旧版 35/56/94 人日是历史估算；本轮没有重新核算，不应直接据此承诺交期。

## 安排开发顺序

以下两项从原始对话要求单独列出，避免只按原型上现有按钮开发而漏掉能力：

| 编号 | 要做什么 | 现状与要交的东西 | 依赖与验收 |
| --- | --- | --- | --- |
| T35 | 硬件与电机参数辨识 | 分开方法和结果，封装客户辨识工具，提供作业状态、原始证据、可信状态与采纳 diff | T04/T11/T15；有激励需批准，失败不覆盖旧值，不支持场景拒绝 |
| T36 | 共用交互功能 | 知识经验增改审查、参数模板、布局保存、模型列表与语音转文字；语音先供人核对 | T03/T06/T07；重启读回、权限校验、模型不可用、识别错词均有测试 |

先做 T01～T05，把保存与权限打通；T06～T11 可在无设备时开发。设备人员同时收齐依赖并处理 T12～T16。随后合并 T17～T25，跑完整模拟流程，再做真实设备验收。T26～T34 应随开发推进，发布前全部复核。

每个任务签收写：负责人、完成提交、测试环境、输入、期望、实际结果、证据文件和未解决问题。不能只写“已接线”“通过”“独立审核过”。任何新的客户要求或现场约束，追加到任务和验收矩阵，保留版本记录。
