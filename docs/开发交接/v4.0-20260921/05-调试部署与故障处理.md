# 调试部署与故障处理 v4.0

先区分两件事：当前能启动的是页面原型及独立验证组件；完成开发后的完整系统还需要业务服务、数据库、工作进程与部署脚本。本文件不给尚不存在的服务编造“一键启动”命令。

## 1. 接手当天：先跑页面

使用团队提供的 Gitee 私有仓权限，在工作目录执行：

```bash
git clone https://gitee.com/zhangjy-george/agent-test-system.git
cd agent-test-system
git rev-parse HEAD
git status --short
cd web
npm ci
npm run build
npm run dev -- --host 127.0.0.1
```

仓库带锁文件，优先 npm ci。Node 版本须满足锁定的 Vite 等包要求，并在 T30 的新机验证后写入版本清单；不要把本机“能运行”当成任意 Node 版本都能运行。以终端实际输出的地址为准，端口占用时 Vite 可能换端口。

首轮检查两个场景、五个流程、知识库、助手开合与按钮。看到回放文字、历史曲线和成功提示，只能说明原型显示正常。打开网络面板记录请求；没有后端请求的按钮不能记作完成。页面构建成功也不证明设备可用。

## 2. 现有设备桥怎样单独检查

桥入口为 `components/spike-device-mcp/bridge.py`，默认本地 8031；运行脚本 `run-bridge.sh` 会处理已有进程，并默认尝试连接台架。共享测试机上不要直接运行该脚本，以免停止他人的桥或连到真实设备。

当前桥没有独立可复现的 requirements 锁文件；导入依赖包括 FastAPI、Uvicorn、Pydantic、Paramiko 及提供 `mcp.server.mcpserver.MCPServer` 的 MCP 包。T01/T30 必须补齐确切发行版、版本和离线安装办法。不能随手安装一个同名 mcp 包就视为兼容。

如果环境已经按组件说明装好依赖，先在独立目录、独立虚拟环境用以下配置检查桥，终端保留前台日志。以下为 Bash 环境变量示意，秘密值须通过本机安全配置注入，不能照抄占位符上线：

```bash
cd components/spike-device-mcp
export BENCH_HOST=127.0.0.1
export BENCH_PORT=1
export FORTIOR_WIN_KEY=''
export BRIDGE_HOST=127.0.0.1
export BRIDGE_PORT=18031
# 另外设置 BRIDGE_TOKEN 和 BRIDGE_APPROVER_PIN，两者非空且不同。
# 不要把秘密写入 VITE_ 变量、命令历史、截图或仓库。
python bridge.py
```

桥不会替你加载任意 .env 文件；确认启动进程实际收到变量。连接测试只使用显式 `force_mock=true` 的模拟连接，核对每个结果的 mode。未连接时显示 unknown；合成结果显示 mock，均不得签成实测。

现有入口包括 `/health`、`/devices`、`/devices/{device_id}/status`、`/devices/{device_id}/tools/{name}`、`/confirmations/{token}/approve`。工具 POST 请求体是 `{"arguments":{…}}`。受保护入口需 `x-bridge-token`；批准额外需 `x-approver-pin` 及操作者字段。完整历史接口说明看旧 08a，但状态以当前源码为准。

本版不要求开发者手工在浏览器配置桥秘密。T15/T30 要用业务服务代转请求，使桥认证留在服务端；批准凭据也不写进浏览器持久存储。现有直连原型与这个目标不等同。

## 3. 按四层联调，每层留下证据

| 层次 | 调什么 | 完成标准 | 禁止跨过去的缺口 |
| --- | --- | --- | --- |
| A 页面＋业务 API | 登录、任务、配置、基线、草稿 | 请求可追踪，刷新和重启后数据一致 | 仍用内存假数据时不能进入正式验收 |
| B 助手＋模拟工具 | 检索、流式回答、全部按钮、批准/拒绝 | 真实模型事件和工具输入输出，模拟标签明确 | 预置回答不能替代模型联调 |
| C 运行＋模拟设备 | 自检、运行、停止、判定、调优、报告 | 完整一次新 run，实际生成报告文件 | 不能拿历史 98 次曲线冒充此次结果 |
| D 现场设备 | 型号/接线核对、只读采集、小范围受控动作 | 现场人员在场，独立急停可用，真实回执及回读 | 阈值、适配器、烧录工具或急停策略缺失则停止该项 |

每层先测成功路径，再测断网、超时、错误输入、取消和重启。现场测试的电压、电流、占空比和持续时间由设备负责人填写批准；本文不提供可直接驱动硬件的默认值。

## 4. 完整系统要交付的部署形态

### 开发机

页面开发服务器、业务服务、数据库、工作进程、模拟桥。模型可真实连接，但设备必须模拟。配置文件只含示例变量名；提交完整依赖锁、迁移和测试种子。启动后 ready 检查数据库和工作进程，不能只返回固定 ok。

### 单台现场主机

推荐第一版交付形态。静态页面由正式 HTTP 服务托管，反向代理转发 `/api/`；数据库、工作进程和桥运行在受控服务账户下。SSE 关闭代理缓冲并设置足够读取超时。设备驱动在现场主机安装，软件只绑定指定网络接口。TLS、登录和防火墙由部署负责人配置。

### 中心服务＋现场桥

中心保存业务与报告，现场执行设备命令。中心断线时现场必须按已确认的安全策略处理，不能依赖中心模型及时回复。现场桥不得直接暴露到公网；链路使用经部署方批准的认证和加密方式。断线恢复按 action_id 对账，不重放未知命令。

## 5. 配置交接表

| 配置组 | 开发者要提供 | 现场人员要填写 |
| --- | --- | --- |
| 服务 | API/页面地址、SSE 路径、监听端口、跨域或同源方式 | 域名、TLS、内网访问范围 |
| 数据 | 数据库连接、文件根目录、容量阈值、迁移版本 | 磁盘、备份位置、保留策略 |
| 模型 | provider、model、超时、并发/成本上限、密钥变量名 | 获授权账号和可用模型 |
| 桥 | 地址、认证变量名、超时、批准时效、模拟开关 | 现场通信地址、设备权限和批准人 |
| 工具 | 编译/烧录/仪器/报告工具路径、版本、参数白名单 | 许可证、驱动、固件工程及模板 |

配置中缺少必需项时启动失败并说明变量名；不得把完整连接串和秘密打进日志。生产配置与开发模拟配置分开，页面始终显示真实/模拟/回放模式。

## 6. 部署负责人必须补的可执行入口

交付一个明确的部署方案即可，不要求同时维护容器和原生两套。提供安装、启动、停止、查看状态、查看日志、备份、恢复、升级和回退的确切命令。命令在一台新环境执行验证，记录 OS、CPU 架构、Node/Python/Rust/数据库版本以及工具版本。

升级步骤：备份并核验可读 → 停止接收新任务 → 等待或安全停止运行 → 记录当前版本 → 执行迁移 → 部署 → 健康检查 → 运行模拟验收 → 开放使用。迁移若不支持回退，必须写清采用恢复备份的方式及数据损失窗口。

## 7. 常见故障怎样定位

| 现象 | 先看什么 | 处理与边界 |
| --- | --- | --- |
| 页面有内容但没请求 | Network、adapter 选择、模式标识 | 可能仍用回放；接真实 API 后再验收 |
| SSE 一直转圈 | HTTP 状态、代理缓冲、done 事件、turn 状态 | 查询原 turn，不重复提交设备动作 |
| 桥返回 mock | mode、连接错误、设备驱动和凭据路径 | 修连接；合成数据不参与正式结论 |
| HTTP 200 但动作未完成 | 业务 status、action_id、设备回执 | 前端按失败处理；不能只检查 response.ok |
| PIN 错误或锁定 | 当前桥 PIN 缺失/错误/锁定均为 403，token 错为 401；429 是新 API 的限流约定 | 查看锁定时刻与角色；等待或管理员处理，不通过重启绕开限流 |
| 写参数后失联 | 动作记录、设备读回、现场状态 | 标记 unknown，停止自动重试，人工核对 |
| 报告有文件但字段空 | 字段映射、工具警告、variable_data 支持 | 逐格检查，不能只看进程退出码 |
| 知识结果串场景 | scene/version/permission 过滤及索引 | 修过滤，重新核验来源和引用 |
| 升级后文件打不开 | 数据库引用、文件路径、SHA-256、权限 | 同时恢复文件与数据库，保留失败日志 |

本轮交付只执行文档、包和发布核验；上述完整系统及现场验收待同事开发后执行，详见 06。
