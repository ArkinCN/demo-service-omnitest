# 验收与交付检查 v4.0

验收对象是实际功能、请求、文件和设备行为。页面弹出“成功”、模型说“完成”、脚本退出码为零，都不能单独作为验收依据。

## 1. 先准备测试环境

准备两个普通用户、一名批准者、一个无权限用户；两个场景；一份可用知识文件、一份坏文件；可确定成功、失败、超时和丢回执的模拟设备；一套报告模板。所有模拟数据带标记，不能混入正式报告。

现场测试另外准备已确认的被测对象、接线图、限值、独立急停、工具和负责人。07 中与现场有关的阻塞未解除时，继续做模拟验收，不跳过限制直接试设备。

## 2. 每项怎么记录

在 `验收矩阵.csv` 填执行人、日期、代码提交、环境、实际结果和证据位置。初始状态“待开发验收”。状态可改为通过、失败、阻塞、不适用；不适用必须写批准理由。`按钮功能清单.csv` 另含两个场景全部按钮，每条必须对应一次实际请求和预期产物。

证据至少包括：请求与响应（脱敏）、对象 ID、数据库或产物变化；涉及页面加截图，涉及设备加命令回执与回读，涉及报告加真实导出文件。保存失败证据，修复后新增一条复测，不覆盖旧失败。

## 3. 必须完整跑通的用户任务

1. 登录，选择场景，建立新任务；导入资料，等待知识索引完成，搜索到带页码/段落的原文。
2. 填产品和硬件资料，读取设备信息，建立真实备份或明确报告无法备份；冻结配置，刷新后读回。
3. 助手根据资料生成要求草稿，人确认阈值、单位和来源后冻结基线；不支持的工作流节点被明确阻止。
4. 自检通过，人工批准指定参数，开始一次新运行；采集数据，生成逐条判定与缺口。保存 run_id 和所有来源。
5. 让助手解释失败并提出候选；查看实际 diff，选定候选，批准后写回、编译、烧录及回读；复跑并比较结果。
6. 选定模板，填充本任务字段和波形，处理缺项，人工复核，生成可下载文件并归档；在外部软件打开核对。
7. 服务重启后找回任务、对话、运行、报告与审计；再用另一用户确认无法越权修改或下载。

第一轮用模拟设备。模拟完整通过且现场条件确认后，再执行受控实机轮次。风扇和汽车包都要验证数据隔离；没有汽车设备时其硬件项标阻塞，不写实机通过。

## 4. 高风险失败场景

| 场景 | 预期行为 |
| --- | --- |
| 同一启动请求发送两次 | 返回同一 action/run，不重复驱动设备 |
| 批准后改了参数或设备 | 原批准失效，要求重新批准 |
| 一次性凭据再次使用、过期使用 | 拒绝并记录，不执行 |
| 错误 PIN 达限制 | 按策略锁定，不泄露 PIN，不可通过换前端绕开 |
| 工具 HTTP 成功但业务失败 | 页面显示失败，不推进阶段、不生成成功报告 |
| 命令已发送但回执丢失 | unknown，禁止盲目重试，提示现场核对 |
| 样本不足、单位不符、仪器异常值 | 缺数据或错误，不伪造不通过/通过 |
| 助手取消或 SSE 断线 | 查询执行状态；不会重复动作或声称设备已停止 |
| 固件编译、烧录、回读任一步失败 | 停止后续链路，显示失败位置与恢复办法 |
| 报告字段缺失、模板不匹配、图片失败 | 阻止正式导出或明确失败，不归档空壳报告 |
| 磁盘满、数据库不可用、工作进程退出 | 明确失败、健康检查异常、恢复后可对账 |

## 5. 页面专项

R-11 必须真人在目标浏览器检查滚动条、嵌套滚动和底部按钮；自动截图只能辅助。R-14 同时记录 B/C 分区与整个首屏的元素数量，并标注窗口尺寸、缩放和计数规则，在负责人确认口径前不写达标。

检查长中文、错误提示、空数据、慢请求、重复点击、两个标签页、切场景、浏览器刷新和返回。按钮置灰要说明缺什么；模拟和回放标识不能只藏在日志里。语音、模型切换等界面若没有对应实现，必须明确不可用或完成开发后再开放。

## 6. 交包前核对

- 提交号、依赖锁、迁移版本、场景版本、工具版本齐全；Git 工作区状态有记录。
- 包内有功能、接口、任务、部署、验收与外部依赖说明；01/02 历史资料若被引用，附来源或定位，不能让同事在不存在的路径找。
- ZIP 解压无 CRC 错误，文件清单与 SHA-256 一致；不含 .env、私钥、数据库密码或访问令牌。
- 全新路径安装和启动，模拟完整流程通过；正式系统未开发完成时，明确只能启动原型。
- 飞书与本地版本对应，入口链接可打开；交付记录写明实际执行了哪些测试，哪些没有执行。

## 7. 本轮核验范围

本轮检查的是已有材料与代码、文档覆盖、附件完整性、Gitee 同步、ZIP 和飞书发布。没有操作现场设备，没有重新烧录，没有完成真实助手联调，也没有代同事实现 T01～T36。最终的实际核验结果记录在 `交付核验记录.md`，不得把这份文档发布成功当成上述功能通过验收。
