## 开工顺序

1. 前端与后端共同跑通无设备的一条真实请求：登录、建测试任务、保存配置、刷新后读回。
2. 接助手的真实模型调用、知识检索和草稿回填。每一步都有请求日志和来源引用。
3. 接模拟设备完成一次运行、判定、调优、复跑和报告文件导出。
4. 设备负责人确认现场条件后，先联只读设备，再联真实动作。真实动作需要人工批准。
5. 在新环境从 Git 克隆、安装、恢复数据并跑验收；通过后再交给使用方。

## 文档采用规则

本目录是本次开发的入口。旧版 03 主文档仍可看图；旧 04、08a～08d 和 05 用来查历史设计、代码快照与证据。旧文件中的“当前”“已完成”都指各自写作时刻，不自动代表本版状态。

本版把要求标为两类：继承已有需求的“必须实现”；此前没有统一方案的“本版建议”。建议项先按契约设计开发，涉及客户阈值、接线和急停策略的事项按 07 文件处理，不能自行填成确定事实。旧接口保持兼容的地方会明确指出，新增接口不声称已存在。

交付包根目录另有文件清单与 SHA-256 校验表。客户原始源码、固件、正式标准、账号和设备凭据由项目负责人通过内部渠道提供；代码包内的引用路径不代表这些材料已经随包交付。
