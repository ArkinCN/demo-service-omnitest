页面逻辑参考峰岹但**不要照抄**（配色、比例、排版可大变）：

典型流程（6 个）：
1. 知识库管理：整个系统的文档与知识管理。两大类：①经验性质（每个流程都有与大模型对话的功能，含语音与打 prompt；过去使用经验的沉淀；需要系统分类与功能设计、呈现方式——没想好，帮设计）②文档性质（测试过程要用的文档，去下面各流程寻找，做好分类；文档要转化成后续流程可用的形态）。有上传文档窗口 + 文档→知识库的转化过程。两类都要有呈现方式与增删改查。体系三级：一级场景（汽车/芯片/电机/…），二级，三级=产品类型；不要第四级；二级只有一个分类也不省略第三级。
2. 初始化配置：第一个窗口是选择产品类型（所有流程的起点，应在最顶端/最开始）。配置有多种：产品描述文档、产品驱动程序、产品功能清单等（上传在知识库处，这里也可有上传窗口）。测试保护/不能违背的原则（如人不能在设备旁否则不能启动、电压绝对不能大于多少伏——名字待定）。功能：读取对应文档→呈现→调整框（左右加减号调数值）。帮想这里应有什么文档。
3. 测试需求确认：测试标准/测试要求/质量要求（由需求给出）；工作流一步步运转，可调整，基于峰岹方法优化；测试案例与成绩不只峰岹电机。
4. 启动测试及结果分析：启动测试功能；没想到需要啥配置/功能，帮想。控制参数是否放这里更好（初始化放本身属性，控制要求不放那边）。安全设置/配置在这边确认，否则测试不能运行。
5. 调优确认及运行：根据测试结果找未达标项，给出推荐调试参数，再回到测试页。
6. 测试报告及产出：模板确认、信息确认等。

总体要求：
- 前端页面直接出
- 找网上好的小工具/开源框架/开源代码辅助设计与产出，有就下载使用
- 流程中用开源工具：skill 积累包（GitHub 很火的项目直接用）、时序折线图小工具（GitHub 很多），不要搬非常大的工程，工具要新
- DSH（DeepSeek Harness）插件网站是另一个非常好的资源库，与 GitHub 同等重视
- 开发人员不懂业务：业务逻辑要写清楚
- 最终发飞书文档，图文并茂、文字尽量少，主要用图和前端页面截图讲清逻辑
