## 2. 用户是谁、口味是什么

用户的全局硬性规则写在 `/home/zzz/.claude/CLAUDE.md`，共 R1 到 R11 十一条，接手模型必须遵守。要点摘录如下，原文以该文件为准。

| 规则 | 一句话要点 |
| --- | --- |
| R1 产出系统化 | 列举必须先分类后展开；同一列表内抽象层级对齐；一句话里顿号串联同类项不超过五个；能无限延长的列表判为偷懒 |
| R2 模型路由 | 用别名不写死版本。常规执行→`sonnet`，复杂任务→`opus`，超长程→`fable`，语言风格敏感的写作→`prose-46` agent（锁 Opus 4.6）。下限锁死 sonnet，任何任务不得降到 haiku。子 agent 的 prompt 一律要求报告搜索范围 |

### 5.2 判据求值规则

实现在 `/home/zzz/agent-test-web/src/features/flow-run/evaluate.ts`（119 行），函数 `evaluateAll()` 在第 88 行起。规则四条：

`evaluable` 为 `false` 或缺表达式的判据，状态记 `manual`，只登记不判。

`variables` 里每个自由变量按 `source` 解析成四类之一：`runtime.measure` 现场实测量、`threshold` 本条自己的阈值字段、`control-parameters` 按键取当前配置值、`constant` 编译期常量。

只要有一个 `runtime.measure` 变量取不到值，整条判「未采集」并列出缺哪几个，不拿别的数顶替、不给结论；未采集的项既不算通过也不算不通过，不进未达标清单、不进调优推荐。

变量齐全时用 `new Function('Math', ...names, '"use strict"; return (${req.criterion});')` 求值，结果转布尔得 `pass` 或 `fail`；求值抛错也记 `missing`。表达式来自本地场景包不是用户输入，允许的全局只有 `Math`。

### 7.7 三条最容易踩的硬约束

安装 DSH 插件时，顶层依赖只能有 `@deepseek-ai/dsh@0.1.5-rc.2` 一个，精确版本不带插入符或波浪号；严禁在顶层单独安装任何 DSH 子插件包，它们已内嵌在主包里，重复安装会提升出第二份更老的作用域包副本，两份互不识别，症状是网页端建会话失败、无头模式每次工具调用报读不到属性。出处 `04-同事实施任务详单-v2.0.md` 第 244 与 254 行。

安全 Hook 必须走 Claude Code 方言的桥，不能走 Codex 方言的桥。Codex 桥会把工具参数压扁成只剩命令字符串，阻断脚本看不到电流限值字段；Claude Code 桥原样传参，是唯一真正生效的阻断路径。两座桥可以都挂着，Codex 那座只做非阻断探针留证。

判据表达式里按位运算与比较运算不得出现在同一括号层。JavaScript 里按位与的优先级低于比较运算符，同层会静默算错，自检脚本的 C10 项专查这个。

**第六条 · 画板的版式与默认视图归场景包，不写死在代码里，也不塞进流程定义。** 每条流程的默认视图由场景包 `scene.json` 的 `default_view` 段下发，经 `adaptScene()`（`/home/zzz/agent-test-web/src/data/loadScene.ts`）拼成 `ScenePackage.ui.defaultView`；页面要显示哪个视图一律走 `useFlowView(flow, scene)`（`/home/zzz/agent-test-web/src/features/canvas`），它做「人点过的 → 场景包下发的 → 代码兜底」三级回落。不要在 `src/data/flows.ts` 的流程定义里加视图字段，也不要让组件自己再 `fetch` 一次 `scene.json`——同一份 JSON 读两遍那笔账在收尾时刚平掉。人摆过的版式按「场景包 × 流程」存在浏览器本地存储里，读写必须包异常捕获，隐私窗口与禁用站点数据时会直接抛。

**关于文件名的一处更正（待核实）**：第三轮的任务口径里曾把这段配置称作场景包的 `canvas.json`。实测两个场景包目录下均无此文件，画板配置实际落在 `scene.json` 里。两个场景包的规范位置是 `/mnt/f/Main/File/2_Projects/峰岹/40_工程/agent-test-web-data/scenes/` 下的 `motor.cooling-fan.fortior-fu6832/` 与 `automotive.body-motor.window-regulator/`。按实测的 `scene.json` 执行，`canvas.json` 这个名字不要再用。

**第七条 · 助手预置按钮的红线降级规则。** 按钮的产出只允许答复、草稿、填表三种，三者都不触发启动、停止、急停、写回参数、导出、归档这六个动作中的任何一个；任何按钮的实现里出现调用这六个动作的接口，即为违规。落地时按三层执行：

1. **分类**。按钮分讲解、准备、执行三类。一轮没跑完时只禁用执行类，讲解与准备类保持可点——整条随忙态置灰会让页面看起来像坏掉了。
2. **降级**。涉及红线的按钮只做到「把人工按钮由灰转为可点」为止，动作本身不执行。界面上要如实回显入参与结果，例如入参写「只把人工按钮由灰转可点，不执行归档本身」、结果写「等待人工确认，未执行」。
3. **放行**。真正执行红线动作只有一条路：设备侧发回 `confirm_token`，界面弹确认条把提示与参数摆给人看，人点确认并带 `operator` 回调放行接口。凭据一次性，MCP 面上进不来。

按钮全量数据落在场景包的 `copilot-actions.json`，不在代码里写死；图标名取值限定在 `/home/zzz/agent-test-web/src/app/icons.ts` 的 `COPILOT_ACTION_ICON_NAMES` 内，取不到时退回通用图标。
