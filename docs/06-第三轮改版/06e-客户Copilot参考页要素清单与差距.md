### 背景补充：图里的模块在客户软件里是什么

读 `峰岹agent/01-架构盘点/v1.0-2026-07-29/AItior软件架构盘点-v1.0.md` 得到三条与看图直接相关的事实。

1. AItior 是 Tauri 应用，启动后在本机 58043 端口拉起 WebSocket 服务，同时承载名为 VibeTesting-MCP 的 MCP（Model Context Protocol）server。
2. MCP 工具分两族：`altior-debug` 提供阶段上报、表单卡请求、符号地址查询、电机启动成败判定等；`keil-c51-tuning` 提供 HEX 烧录与在线调试。
3. `resources/data/dc-skills/` 下有 25 个技能目录，每个目录一份 `SKILL.md`，按调试阶段分组，覆盖需求初始化、硬件自检、启动调优、运行调优等。

由此可推断：画布上的设备节点与右侧工具条的按钮，背后调用的就是这批 MCP 工具，副驾的「开启自动调试」按钮背后挂的是这批 skill。这是推断，未抓包核实。

按"为什么不该抄"分四类。

### 4.1 属客户芯片业务、通用测试系统没有对应物

参考页的四个主阶段是需求评估、硬件设计、软件设计、可靠性验证，场景是初始化配置与需求确认，这套轴对应的是电机驱动芯片的开发流程。通用 Agent 测试系统的阶段轴是测试流程轴，两者不是同一维度，照抄会把产品定位拖回芯片调试工具。

同类的还有画布上默认摆的主控引脚图与驱动电路原理图。那是芯片厂自己的资产，通用系统的画布默认内容应由接入的被测对象决定。

### 4.2 属客户 MCU 开发链路的能力

右侧工具条的 MCU 调试组，背后是 HEX 烧录与在线调试。通用测试系统面向的是被测设备的测试与判定，不承担编译烧录。这一组不该原样出现在我方工具条里。

同理，「可点击打开源代码」这条交互，前提是工作区里有客户的 Keil 工程。我方画布节点的双击行为应指向证据与数据，不指向源码。

### 4.3 我方现状已经更好、抄过去等于退化

参考页的权限只有「完全访问权限」一档。我方已有只读、可改参数、可控硬件三档，外加只读工具免确认开关。安全联锁是本项目的硬要求，权限粒度只能加不能减。

参考页的副驾没有把执行结论沉淀回知识库的入口。我方已有「沉淀为经验」与「依据 N」，这条链路要保留。

### 4.4 语域与形象上不适配

参考页的助手有拟人化昵称与卡通吉祥物头像，开场白写成「现在要开始电机驱动开发之旅吗？」。本项目面向技术客户，已定的语气规约排斥这类生活化表达。副驾的身份区照抄结构可以，文案与形象不照抄。
