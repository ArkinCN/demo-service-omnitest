## 〇、编号规则、严重级与执行方式

### 0.1 用例编号规则

编号形如 `AC-<域字母>-<功能点两位>-<序号两位>`。

| 段 | 取值 | 含义 |
| --- | --- | --- |
| `AC` | 固定 | acceptance case，验收用例 |
| 域字母 | A / B / C / D / E | 五个域，见第一节各自小节标题 |
| 功能点两位 | 01 至 99 | 域内的功能点序号，在各域开头的功能点表里定义 |
| 序号两位 | 01 至 99 | 同一功能点下的用例序号 |

举例：`AC-A-03-02` 是需求符合性域、功能点 03（画布滚轮缩放，对应录音意见 R-03）、该功能点下第 2 条用例。

编号一经发布不回收、不复用。用例作废时保留编号并在总表里标「作废」，新增用例在所属功能点末尾续号。

### 0.2 严重级定义

| 级别 | 定义 | 处置 |
| --- | --- | --- |
| 阻断 | 不修复则不能交付、不能对客户演示。包含：任何一条业务红线失守、构建或类型检查不过、页面白屏或报错中断、把待核实值当确定值对外呈现 | 必须修复后重跑该用例，不接受绕行 |
| 主要 | 不修复不影响系统跑起来，但会使某条用户意见判为未落地，或使验收结论从通过降为有条件通过 | 修复或由用户书面豁免，二者取一 |
| 次要 | 观感、文案、文档层面的问题，不影响功能与结论 | 记入遗留清单，可在下一轮统一处理 |

### 0.3 执行方式三类

| 方式 | 定义 | 产出的证据形式 |
| --- | --- | --- |
| 自动脚本 | 一条命令或一支脚本跑完即给出通过与否，不需要人介入判断。含构建命令、静态扫描、Playwright 断言、场景包自检、MCP 取证脚本 | 命令原始输出落盘为文本文件，文件名带用例编号与执行时间 |
| 人工操作 | 需要人在真实浏览器或真实台架上操作一遍，操作本身脚本替代不了。含真人浏览器滚动、台架通电、示波器接线、换包演示彩排 | 操作记录加截屏或录屏，注明执行人、时间、所用环境 |
| 人眼检视 | 对着截图或页面逐项数、逐项看，判据是计数或有无，不是感觉。含元素计数、状态色计数、裁切与叠压检查 | 标注过的截图，或计数表格，逐项写出数到的值 |

三类之间不可互相替代。特别是「代码里写了 `overflow-y: auto`」不能替代「人在真实浏览器里看见滚动条」，这正是 R-11 至今没有闭环的原因。

for (const scene of SCENES) for (const path of PATHS) {
  const page = await ctx.newPage()

  page.on('console', m => m.type() === 'error' && !IGNORE.test(m.text()) && errs.push(m.text()))
