## 1. 新信息架构：知识库降为基础模块

### 1.1 六流程变五流程

用户口径（R1、R2、R5）是三层意思：知识库不是必有流程、它比 2–6 更底层、后面五个流程各自都要有上传与管理知识的入口。据此提案：

| 项 | 现状 | 改后 |
| --- | --- | --- |
| A 区流程 stepper | 六步，第 1 步是「知识库」 | 五步，编号 1–5，即初始化配置 / 测试需求确认 / 启动测试及结果分析 / 调优确认及运行 / 测试报告及产出 |
| 知识库入口 | 占第 1 个流程标签 | A 区右端常驻一枚图标按钮，旁挂条目数；点击进入知识库独立页面 |
| 各流程内的知识入口 | 无 | 每个流程页 B 区顶部加一条「本流程可用知识」，含上传按钮与筛选后的条目数，点开是抽屉不是换页 |
| 代码标识 `kb` | `FLOW_IDS` 的第一个 | 移出 `FLOW_IDS`，另立 `MODULE_IDS`，路由从 `/kb` 改到 `/knowledge` |

编号是否重排是需用户拍板的一条，见第 7 节。

### 1.3 知识分类：三轴而不是一棵树

现有设计只有两个维度——归属（三级场景树）与来源（文档 / 经验两大类），用户问的「工艺 / 测试需求 / 产品说明书」是第三个维度：**这份材料回答什么问题**。三个轴互相正交，任何一条知识同时落在三个轴上。

**轴一 · 归属（挂在哪个产品下）**，三级，已实装，数据在 `public/scenes/index.json`：

```
一级 场景：电机 / 汽车 / 通用
  二级 子类：散热风扇 / 家电电机 / 车用电机 / 车身电机 / 通用规范
    三级 产品类型：FU6832 散热风扇驱动板 / 电动玻璃升降器 / …
```

**轴二 · 来源（谁产生的）**，两类，已实装：文档类由外部上传，基本不变；经验类由系统自己用出来，一直在长。

**轴三 · 用途（回答什么问题）**，三类，本轮新增：

```
用途轴
├─ 产品说明书类 —— 回答「这个被测对象本身是什么样」
│    文档：产品描述、驱动与固件、功能清单、原理图
│    经验：（一般不产生）
├─ 测试需求类 —— 回答「要测什么、算合格的线在哪」
│    文档：标准与规范、报告模板
│    经验：判据修正
└─ 工艺类 —— 回答「怎么测、出了问题怎么调」
     文档：测试规程、历史报告
     经验：问答、调参决策、失败案例
```

八个既有文档类型与四个既有经验类型全部落位，不新增也不遗漏类型。其中两处归属有争议，列入第 7 节待拍板：报告模板归「测试需求」还是另立「产出模板」，历史报告归「工艺」还是「测试需求」。

界面落法：知识库页面左栏是三个可折叠的筛选器而不是一棵树，三轴任意组合出条目集；条目列表上方给一行面包屑写清当前三轴的取值。

### 1.4 知识库自己的页面

用户明确要求（R6）：不套四块统一页面，但保留 D 区副驾对话框，其余三块自排。提案是**两栏加一条底栏**：

| 区 | 内容 | 占比 |
| --- | --- | --- |
| 顶条 | 面包屑（三轴当前取值）+ 转化流水线状态（已转化 / 切片 / 抽图 / 待转）+ 上传按钮 | 通栏，高 56 |
| 左栏 | 三轴筛选器，三个 `Collapsible`，默认只展开归属轴 | 宽 300 |

与流程页的区别一眼可见：没有流程 stepper、没有动作条上的启动类按钮、没有卡片网格、没有右侧竖工具条。相同的只有顶栏品牌位与副驾。

## 2. C 区重做：统一画板

### 2.1 用户要的是什么

录音三条合起来看（R3、R4、R7、R16）：整块面板像地图那样用鼠标滚轮缩放、外框尺寸不变；里面不再切成几个功能块，而是一块统一画板，仿物理连接把几样东西连起来；右侧工具条可以往中间拖拽功能模块；设备以 MCP 的形式集成进画板，SSH 只是后台通信链路，不为它单独开页面。参考页 `_调研/ref-客户Copilot页面-用户提供-20260919.png` 的右上区正是这个形态——示波器截图、笔记本电脑图标、芯片引脚图、原理图、程控电源五个对象散布在一块画布上，两两之间有连线，右侧三组竖向工具（波形采集 / 环境控制 / MCU 调试），左下角 100% 缩放与复位。

### 2.2 节点类型清单

按「这个节点代表什么实体」分五类，类内不超过五项：

| 类 | 节点 | 卡面主要内容 | 对应现有卡片 |
| --- | --- | --- | --- |
| 被测对象 | 产品实物、原理图、芯片引脚图、工程源代码 | 图为主，点开进放大态 | `product-view`、`schematic`、`project-tree` |
| 测量设备 | 示波器、转速读取、电参数测量 | 设备照片或面板缩略 + 在线状态点 | `bench-live`、`remote-device` |
| 激励与环境 | 程控电源、逆风风扇、温箱 | 当前设定值 + 状态点 | 工具条「环境与激励」组 |
| 过程与数据 | 工作流、时序数据集、判定表、执行进度 | 曲线 / 拓扑 / 计数 | `workflow`、`timeseries`、`verdict`、`progress` |
| 服务与连接 | MCP 服务节点、安全联锁盘 | 已挂载工具数 + 健康状态 | `tools`、`interlock` |

「被测对象」与「测量设备」之间的连线表达信号走向，边上标通道名（CH1 接 FG1、CH3 接 PWM1 这类，取自场景包的通道映射）；「被测对象」内部各节点之间的连线表达从属（原理图属于这块板）。连线语义仍只有从属与信号走向两种，与 `01-设计规格-信息架构与页面-v1.0.md` 第 7.1 节一致，不参与任何计算。

### 2.3 设备怎么以 MCP 节点出现

用户否掉的是「为 SSH 单独做一个页面」，不是否掉 SSH 本身。分层改法：

1. **画板上只有 MCP 服务节点**。一台设备在画板上是一个节点，节点属性里写它挂了哪几个工具、当前健康状态、以及接入形态（数据拉取 / 命令行会话 / 远程桌面 / 独立窗口）。
2. **SSH 退到后台**。`~/lab/webssh` 的网关（Node + express + ws + ssh2，私钥只在网关侧）保留，但不再对应任何一张卡或一个页面，降级为「命令行会话」这一种接入形态的实现细节。
3. **终端只在放大态出现**。需要跑脚本取文件时，从 MCP 节点的放大态里开终端，关掉即回画板。现有 `src/features/remote/RemoteTerminal.tsx` 与 `RemoteDeviceCard.tsx` 保留代码、改挂载位置。
4. **卡片库里的 `remote-device`「单机设备会话」取消独立卡槽**，并入服务与连接类节点。

### 2.4 缩放与拖入的交互

| 行为 | 做法 |
| --- | --- |
| 缩放 | 鼠标滚轮以指针位置为锚点缩放，范围 0.4×–2.5×；外框（C 区容器）尺寸与位置完全不变，只有内容缩放 |
| 平移 | 空白处按住左键拖拽，或中键拖拽；触控板双指平移 |
| 复位 | 左下角显示当前百分比，旁边一个复位按钮回到 100% 并居中，位置与参考页一致 |
| 概览 | 右下角缩略导航图，画板内容超出视口时才出现 |
| 拖入 | 右侧竖工具条的按钮可拖，拖到画板落点即在该处创建对应节点；落点之外放手则取消 |
| 记忆 | 人摆过的版式按「场景包 + 流程」记住，下次进来还原；场景包下发一份默认版式作为初始值 |

### 2.5 画板与卡片网格的关系

现有六页都是 3 列 2 行卡片网格加一个「网格 / 画布」分段切换（`src/app/ResourcePanel.tsx`），画布视图是自研的绝对定位加 SVG 连线，**没有缩放、没有拖拽、没有拖入**，这正是用户说「画布功能没看到具体呈现」（R7）的原因。

提案：**画板升为默认视图，网格退为次视图**。理由是用户两次强调参考页「就是一个统一的画板」。保留网格是因为长时间盯状态时网格更省眼，这条理由写在 `05-交接文档-给接手模型-v1.0.md` 第 6.2 节，仍然成立。每个流程的默认视图写进场景包的界面配置，不写死在代码里：

| 流程 | 建议默认视图 | 理由 |
| --- | --- | --- |
| 1 初始化配置 | 画板 | 要讲清楚测的是哪块板、探头接在哪 |
| 2 测试需求确认 | 画板（工作流拓扑占主位） | 本来就是一张图 |
| 3 启动测试及结果分析 | 网格 | 跑测试时要并排盯曲线、判定、联锁三样 |
| 4 调优确认及运行 | 网格 | 要并排比历史波形与候选队列 |
| 5 测试报告及产出 | 网格 | 报告预览需要大面积连续版面 |

### 2.6 技术选型

**推荐 React Flow（`@xyflow/react` 12.11.6），不自研 SVG。** 三条理由：

1. **已经是依赖，已经在用**。`/home/zzz/agent-test-web/package.json` 里已有 `@xyflow/react` 与 `dagre`，工作流画布 `src/features/workflow/components/WorkflowCanvas.tsx` 已用它渲染了客户归档的 68 个 `.wfw` 文件，不引入新依赖、不增加打包体积。
2. **要的四样它都内置**：以指针为锚点的滚轮缩放、拖拽平移、`MiniMap` 缩略导航、`Controls` 缩放条，以及从外部 DOM 拖入创建节点的 `onDrop` 通路。自研这四样是纯重复劳动。
3. **节点可以直接复用现有卡片**。React Flow 的自定义节点就是一个 React 组件，把现有 `PanelCard` 加 `CardArt` 包一层即可，卡头图标、状态点、放大按钮全部沿用，视觉不破 `DESIGN.md`。

许可证为核心 MIT，`05-交接文档-给接手模型-v1.0.md` 第 6.3 节已核实。被排除的候选同处有记录：tldraw 许可禁止生产使用，Rete.js 的分组嵌套挂在禁商用插件上，LiteGraph.js 与 Drawflow 已停更。

实现位置：新建 `src/features/board/`，把 `ResourcePanel.tsx` 里的 `CanvasView` 整个替换掉；工作流画布作为画板上的一类节点嵌进去，两处不再各写一套画布。

**任何同级列表超过 5 项，必须先分组再展开；分组超过 3 组，默认只展开第一组，其余折叠。** 这条同时管界面与文档：界面上是 `Collapsible` 的 `defaultOpen`，文档里是小标题与表格。

## 5. 副驾升级（R15）

### 5.1 页面上下文注入

用户口径是「参考页的 copilot 能根据当前页面或当前阶段把信息给到副驾」。做法是每次发消息时，前端打一个上下文信封随消息一起送给模型，信封分四组：

| 组 | 字段 |
| --- | --- |
| 位置 | 当前流程标识、场景包标识、三级产品路径、当前视图（画板 / 网格） |
| 选中 | 当前聚焦的画板节点或卡片标识、该节点的摘要行 |
| 左栏状态 | 输入清单的完成数与未完成项、已展开的分组、人工改过的参数的前后值 |
| 闸门与轮次 | 安全联锁的满足计数、当前轮次号、最近一次工具调用的名称与结果 |

实现位置：`src/state/useAppStore.ts` 加一个 `selectContext()` 选择器，`src/features/copilot/adapter.ts` 在发送前调它。参数值只送人改过的那几项的 diff，不送全量 70 项。

### 5.2 按钮就是预置 prompt 或 skill

现有 `quick` 字段是纯字符串数组（`src/data/loadScene.ts`，六处），点了只是把文字填进输入框。要改成结构体：

```ts
interface CopilotAction {
  id: string
  label: string          // ≤6 字，配图标
  kind: 'prompt' | 'skill'
  prompt?: string        // kind === 'prompt' 时，模板串，{{}} 占位由上下文信封填
  skill?: string         // kind === 'skill' 时，DSH 技能名
  needs?: string[]       // 前置条件，不满足则置灰并在 tooltip 说明差什么
  produces: 'answer' | 'draft' | 'fill'  // 产出形态，三种都不落盘
}
```

按钮摆在输入框正上方一行，与参考页的「开启自动调试」位置一致。每流程 3–5 个：

**初始化配置**

| 按钮 | 做什么 | 产出 |
| --- | --- | --- |
| 读取并填充 | 从数据手册、`Customer.h`、原理图回填 29 项本体属性 | fill，填进表单标「建议」，提交并锁定仍由人点 |
| 核对链路 | 比对通道映射与原理图上的端子 | answer |
| 哪些是占位 | 列出 5 项 `_placeholder` 及其缺口原因 | answer |
| 拟联锁清单 | 按联锁模板草拟 19 条的默认阈值 | draft |

**测试需求确认**

| 按钮 | 做什么 | 产出 |
| --- | --- | --- |
| 抽判据 | 从选中规程章节抽出判据与表达式 | draft |
| 推荐工作流 | 从 68 条归档工作流里挑本轮适用的 | answer |
| 哪些不能自动判 | 列出 6 条只能人工判的及其原因 | answer |
| 备好基线 | 把本轮选中项打包成需求基线草稿 | draft，冻结由人点 |

**启动测试及结果分析**

| 按钮 | 做什么 | 产出 |
| --- | --- | --- |
| 跑预检 | 逐项查设备连通、通道、基线 | answer，**不启动测试** |
| 解读波形 | 算选中曲线的峰值、稳态、首响时间 | answer |
| 为什么判不通过 | 对着判据逐条给实测值与阈值的差 | answer |
| 备好闸门 | 列出 9 条安全确认闸门里还差哪几条 | answer，**逐条确认由人点** |

**调优确认及运行**

| 按钮 | 做什么 | 产出 |
| --- | --- | --- |
| 为什么是这几项 | 给候选队列每条的经验依据编号 | answer |
| 影响面 | 算改这几项会牵动哪些判据 | answer |
| 拟写回草稿 | 生成参数改动版本草稿，沿用原数值外壳 | draft，**写回由人点** |

**测试报告及产出**

| 按钮 | 做什么 | 产出 |
| --- | --- | --- |

### 5.3 红线

**启动、停止、急停、写回参数、导出、归档这六个动作一律人点。** 副驾按钮的 `produces` 只能是 `answer`、`draft`、`fill` 三者之一，三者都不触发这六个动作中的任何一个；任何按钮的实现里出现调用这六个动作的接口，即为违规。这条与 `05-交接文档-给接手模型-v1.0.md` 第 0 节第 9 句、`04-同事实施任务详单-v2.0.md` 第 12.1 节一致，本轮不放宽。
