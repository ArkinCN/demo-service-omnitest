# 场景包：汽车 / 车身电机 / 电动玻璃升降器（含防夹）

`scene id = automotive.body-motor.window-regulator`

这是网页原型的**第二个场景包**，与第一个包（`motor.cooling-fan.fortior-fu6832`，峰岹散热风扇驱动板）
同构：同样的 10 个 JSON、同样的字段名、同样的 `_source` 约定、同样的 `_build/` 脚本布局。
它要证明的是一件事——**换场景只换包，前端与画布不用改**。

两个包在「通用层」（电压、温度、盐雾、电磁兼容）完全重合，在「产品层」完全不同。
这正是知识库三级分类设计的实证依据：二级判据跨场景复用，三级判据逐产品定义。
逐格对照见第八节。

## 三、通用字段约定

与第一个包完全一致，另加两条本场景新增的（3.4 与 3.5）。

### 3.1 `_source`（每条数据都有）

```json
"_source": {
  "file": "/mnt/f/Main/File/2_Projects/峰岹/10_外部资料/汽车场景素材-20260919/qc636.txt",
  "locator": "qc636.txt:119-120 5.4.1 b) 「工作电流不大于12A」"
}
```

- `file` 一律是**绝对路径**，可独立定位，不依赖本 README 的上下文。
- `locator` 给行号、条款号、PDF 页码或小节标题。
- 某条结论靠多份材料互证时，`_source` 是数组。
- 大量条目的 `_source` 指向素材综述文档
  `/mnt/f/Main/File/2_Projects/峰岹/峰岹agent/09-实验室demo线/20260919-通用Agent测试系统v2.0/_调研/B-汽车场景测试案例素材.md`
  的具体行号（`第 N 行：……` 形式）。凡是能直接指到证据原件的，同时给证据原件的路径与条款号。
- 本次构建**没有任何条目落空**（`_source` 全部非空，生成报告的「未找到项」为空）。

### 3.2 `_placeholder`

值为 `true` 表示**这个数值是编的**，源材料里没有，前端应显式标注「待确认」，不得直接当真值用。
本包共 37 处，逐条见第五节。

### 3.3 `_status`（本场景的重头）

值为一句话，说明这条数据为什么不算「已核实」。最常见的一句是：

```json
"_status": "待核实（QC/T 626-2019 正式版可能调整）"
```

**本包的本体性能数值几乎全部带这个标记。** 原因是 QC/T 626-2019 正式版的全文
（行业标准信息服务平台以「潜在版权问题」不公开，需采购）本次没拿到，
能用的是中国汽车技术研究中心有限公司（CATARC）官网公开挂载的《汽车玻璃升降器》
行业标准征求意见稿 16 页 PDF——**文件本身已核实（本次下载并逐条提取），
但其数值相对正式版可能调整**。

带 `_status` 的对象共 **188 个，占带源对象的 59.7 %**。这个比例高是如实反映，不是质量问题：
它说明本场景当前处在「判据结构齐了、数值待正式版确认」的状态。

与之相对，下面这些是**已核实**、不带 `_status` 的：

- 防夹的 100 N 与 4 至 200 mm 与 (10 ± 0.5) N/mm（GB 11552-2009 §4.8.3.1，本次从条文 PDF 文本层逐字提取）
- ISO 16750-2:2023 的供电电压代码、长时过电压、跨接启动、瞬态过电压
- ISO 16750-4:2023 的工作温度代码
- VW 80000 的 M-04 谱型 D 与 M-06 冲击次数
- LV 124 / VW 80000 试验 E-15 反极性（原文点名电动车窗）
- AEC-Q100 Rev J1 的温度等级表
- Microchip MCAF 7.0.2 的五个电流环整定参数
- NHTSA FMVSS 118 合规报告的六节结构与 13 字段著录页

### 3.4 可调参数的六件套

`product-attributes.json` 与 `control-parameters.json` 里每项都带：

- `value` 当前值、`default` 默认值
- `unit` 单位
- `min` / `max` / `step` —— 给前端左右加减号用
- `editable` 是否允许调

另有三个补充字段：

- **`options`** 非空表示这是**枚举参数**，前端应出下拉框而不是加减号；此时 `min`/`max`/`step` 一律为 `null`。
  形状是 `[{value, label}]`（与第一个包一致），`value` 是写回去的值，`label` 是给人看的中文。
  本包共 20 个枚举参数：`product-attributes.json` 11 个、`control-parameters.json` 9 个。
  例：`antipinch_retract_mode` 的五个回缩策略、`test_rod_stiffness` 的 10 与 20 N/mm、`motor_type` 的三种。
- **`range_estimated: true`** 表示 `min`/`max` 区间是本包按物理约束推定的，**源材料没给区间**。
  前端不应把它当成标准规定的可调范围。
- **`not_applicable: true`** 表示这一项对本产品类型不适用。本包只有一处：`pole_pairs` 极对数——
  有刷直流电机不做无刷意义上的极对数配置，与之对应的可配量是每转纹波数（= 2N，N 为绕组对数）。

### 3.5 判据的可求值性：`criterion` / `evaluable` / `variables`

与第一个包**完全同一套契约**（该包已按核验意见改定，本包照抄）。
`test-requirements.json` 的每条要求带四个配套字段：

| 字段 | 含义 |
| --- | --- |
| `criterion` | **JavaScript 表达式（ECMAScript），求值结果为布尔**。散文式、无可测量量可取的条目为 `null` |
| `evaluable` | `false` 表示这条不是对测量结果的判定，此时另有 `not_evaluable_reason` 写明卡在哪 |
| `variables` | 把表达式里每个自由变量映射到确定的取值来源 |
| `criterion_text` | 人读版本 |

`variables[].source` 四种取值：

| source | `ref` 指向 | 本包用例 |
| --- | --- | --- |
| `runtime.measure` | 顶层 `runtime_measures` 登记表里的运行时测量量 | `peak_pinch_force_n`、`rise_speed_mm_s` |
| `threshold` | 本条自己的 `threshold` 字段 | `max_force_n`、`opening_min_mm` |
| `control-parameters` | `control-parameters.json` 的 `parameters[].key` | `antipinch_retract_mode`、`startup_blanking_time` |
| `constant` | 编译期常量，`derived_from` 指向 `safety-interlocks.json` 的 `fault_bitmap` | `FAULT_REVERSE_POLARITY = 128` |

顶层另有 `criterion_syntax`、`criterion_globals`（`["Math","true","false","null"]`）、
`runtime_measures`（本包登记 **59 个**运行时测量量，全部 59 个都被判据引用，无冗余登记）、`evaluable_count`、`not_evaluable_count`。

34 条要求里，**31 条 `evaluable: true`，全部已用 Node.js 实际求值通过且返回布尔**；
3 条 `evaluable: false`（TR-RULE-01 型式检验分组与抽样、TR-RULE-02 外观与涂镀层、
TR-RULE-03 用户手册），`criterion` 为 `null` 并各带一句 `not_evaluable_reason`。

三条硬规矩：

1. **表达式里出现的每个自由标识符都必须在 `variables` 里有条目**（`Math` 与字面量除外）。本包已逐条校验。
2. **阈值不写成字面量**，一律经 `threshold` 引一层。换温度档时只改 `threshold`，表达式不动——
   例如 TR-BASIC-03 换 80 ℃ 档就是把 `threshold.max_a` 换成 `max_a_80c` 的值。
3. **位运算一律加括号。** `&` 的优先级在 JS 与 C 里都低于比较运算符，
   写成 `fault_flags & FAULT_REVERSE_POLARITY !== 0` 会被解析成
   `fault_flags & (FAULT_REVERSE_POLARITY !== 0)`，结果全错。
   本包唯一用到位运算的是 TR-ELEC-08，写作 `(fault_flags & FAULT_REVERSE_POLARITY) !== 0`。

`runtime_measures` 与第一个包的差别：那边的测量量大半由示波器与 HID 指令取
（`rigol_measure FREQ`、`breakrun + readmem` 等），
这边全部由台架传感器取（力、位移、电流、声级计、环境箱），
还有一部分是人工检查的布尔量（拆机目视、遥控距离验证）。

## 四、各文件字段说明

### 4.1 `scene.json`

`taxonomy` 三级分类 · `product` 产品名与控制方案 · `summary` 简介 · `images` 图片引用（含渲染参数与像素尺寸）·
**`regulation_matrix` 三地防夹法规对照**（中国 GB 11552-2009 / 美国 FMVSS 118 / 欧洲 UN ECE R21，
逐格给力限值、开口范围、试验棒刚度、回缩后位置选项）· `regulation_note` 三地都不强制配备防夹这一事实 ·
`flows` 六流程。

`regulation_matrix` 是本场景相对第一个包全新的一块：第一个包没有「同一判据在三个司法辖区有三套口径」这件事。

### 4.2 `product-attributes.json`

47 项，分 8 组：电机本体 / 电气额定 / 工作电流 / 机械性能 / 运行速度 / 声学 / 结构与行程 / 环境与等级。

量纲与第一个包完全不同：那边是转速 rpm、相电流 A、温升 K；这边是线速度 mm/s、力 N、位移 mm、声压级 dB(A)。

### 4.3 `control-parameters.json`

59 个参数，分 7 组：

| 组 | 参数数 | 与第一个包的关系 |
| --- | ---: | --- |
| 防夹算法 | 11 | **全新**，第一个包没有任何对应物 |
| 位置与行程 | 7 | **全新**（纹波计数、霍尔脉冲、软停） |
| 驱动与调制 | 5 | 部分对应（PWM 占空比、载波、死区） |
| 保护与热管理 | 13 | 概念对应（过压、欠压、过流、堵转、热保护），阈值全换 |
| 电流环整定 | 6 | **完全共用**，来自 Microchip MCAF 7.0.2 |
| 台架与工装 | 13 | **全新**（试验棒、环境箱、泥水、喷水、耐压） |
| 数据采集 | 4 | 概念对应 |

`adjustable_in_flows` 标这个参数在哪个流程里允许改。同一个参数可能在多个流程出现，
但含义不同：F2 是确认初值，F5 是未达标后回调。

### 4.4 `safety-interlocks.json`

21 条，按 `type` 分三类（与第一个包同）：

- **硬件** 10 条：由固件阈值或仪器状态判定
- **流程** 6 条：由规程纪律约束执行顺序与动作
- **人员** 5 条：需要操作者显式确认才能放行

`fault_bitmap` 是**示例位图**（`_placeholder: true`）：本场景没有客户固件源码，
位定义是本包按已登记的保护项编的，用于让前端的位运算判据有东西可解，
**不得当作任何真实产品的接口定义**。

最关键的一条是 `SI-HW-01` 防夹力上限——这是全包唯一一条**人身安全**性质的硬顶，
也是本场景相对第一个包（全部为设备安全）的本质差异。

### 4.5 `test-requirements.json`

34 条，分 6 类：基本性能（8）/ 自锁（1）/ 防夹（7）/ 环境与耐久（7）/ 电气与防护（8）/ 检验规则（3）。

最有演示价值的是防夹那一组里的 TR-PINCH-01 / TR-PINCH-03 / TR-PINCH-04：
**同一个物理试验、同一次采集，在中、美、欧三地是三套判据。**
三地在 100 N 与 4 至 200 mm 上完全一致，差异只在试验棒刚度（10 vs 20 N/mm）
与回缩后位置（多开 50 mm vs 多开 125 mm）。换目标市场即换判据表。

### 4.6 `workflows.json`

**本场景没有任何现成的 `.wfw` 文件。** 第一个包有 67 个客户真实工作流可解析，这边是零。

所以这 4 条全部是本包按第一个包的结构造的示例，每条都带 `_placeholder: true`。
它们证明的是「同一套画布与索引结构能装下新场景」，不是「客户已有这些工作流」。

节点用**六类抽象**，每条工作流 10 个节点、六类齐全：

| 类 | 说明 |
| --- | --- |
| 设置 | 把台架与被测件置于试验要求的初始状态（电压、温度、配重、工装位置、固件参数） |
| 激励 | 对被测件施加动作或应力（升降指令、施加障碍物、施加加载力、施加过压） |
| 采集 | 从传感器与被测件读数（电流、位移、力、声压、故障字） |
| 判定 | 拿采集到的量与 `test-requirements.json` 的判据比对，出 PASS / FAIL |
| 控制流 | 流程骨架（开始、结束、延时、循环、跳出、条件分支） |
| 数据处理 | 从原始时序算出判据需要的派生量（速度、峰值、偏差、纹波计数），以及导出报告 |

`assets/workflows/*.json` 用的是工作流画布组件的**统一内部模型**
（`{ nodes, edges, meta, variables }`，见 `~/lab/workflow/README.md` §3.1），
可直接喂给 `WorkflowCanvas`，不需要经过 `parseWfw`。

`sourceHandle` 承载分支语义：`output` 主干画墨绿实线、`error` 异常出口与 `false` 假支画暗红虚线、
`true` 真支。每个非起止节点都拉一条 `error` 边到公共异常出口，所以连线数多于节点数——
这个做法是从第一个包的真实 `.wfw` 文件里学来的。

本包的 37 个节点类型与第一个包那 25 个峰岹客户端专有类型（`hid_preset_*`、`rigol_oscilloscope` 等）
**没有一个重合**。这正是「换场景只换包」要证明的：画布与索引不变，节点词汇表随包走。

### 4.7 `datasets.json`

3 条，**全部是合成的**（`synthetic: true` + `_placeholder: true`），24 000 行 × 10 列、2 000 Sa/s、12.0 s。

为什么只能合成：汽车低压执行器电机（雨刮、车窗、天窗、座椅、EPS、节气门）的专用公开波形数据集，
在十三个数据平台上检索确认为**空白**。这是检索证实的结论，不是遗漏，
十三个平台逐个列在 `why_synthetic.platforms_searched` 里。

合成模型、参数标定口径与三条工况的设计意图见第六节。

另有 `real_data_alternatives` 三条**只登记不下载**的真实数据集（CARTIF 有刷直流故障集、
帕德博恩车用电机温度集、帕德博恩轴承集），以及 `excluded_datasets` 里 5 条已排除与 2 条存疑的条目——
后者是为了避免后续重复捞。

### 4.8 `experience.json`

18 条，每条 = 现象 `symptom` / 原因 `cause` / 动作 `action` / 结果 `result` / 标签 `tags` /
证据档位 `evidence_level` / 来源 `_source`。

与第一个包的分野很清楚：那边的 `evidence_level` 有「台架实测数据」「判定工具输出」两档，
本场景**一条都没有**，因为没有实物台架。反过来本场景多出「法规条款」「标准状态」「来源状态」三档，
因为它的知识全部是可被第三方复核的公开材料。

每条的 `_source` 都给到论文/文档的**完整标题 + 出处 + URL**，不只给编号。

### 4.9 `documents.json`

83 份，分 31 类。其中 **29 份有本地副本**（`exists: true`），其余只有编号、全名、URL 与状态。

四份 OEM 规范（LV 124 / VW 80000 / LV 148 / BMW GS 95024-3-1）的本地副本
**均为公网流传的非授权版本**，内容可信但不具备引用资格，
已单独列在 `non_authorized_copies` 里，正式引用前须经采购渠道取得授权原本复核。

`version_change_alerts` 是知识库必须内置的**换版预警元数据**，共 7 条。
QC/T 626 征求意见稿引用的三本标准（GB/T 18655-2010、GB/T 21437.2-2008、GB/T 10125-2012）
都已换版，落地前必须逐条改引现行版。

与第一个包的链路差异：那边 61 份文档绝大多数是**客户私有文档**，走「上传 → 解析 → 入库」；
这边全部是**公开标准、法规、参考设计与论文**，走「标准编号 → 条款抽取 → 判据结构化」。

### 4.10 `report-template.json`

骨架来自 NHTSA FMVSS 118 合规报告样张 REPORT NUMBER 118-GTL-11-002（36 页全文在手）：
**六节结构 + 13 字段技术著录页 + 15 张编号照片**。

第一个包的模板是 Excel（`.xlsm`），字段定位用 `label_cell` / `value_cell` 两个单元格地址。
本场景的模板是 PDF 报告，没有单元格，**同一个概念落成「节 + 字段」两级**：

| 第一个包 | 本包 | 含义 |
| --- | --- | --- |
| `label_cell`（如 `A11`） | `label_section` + `label_slot` | 字段标题位 |
| `value_cell`（如 `B11`） | `value_slot` | 字段取值位 |

前端渲染器只要认「一个标题位 + 一个取值位」这个抽象，两个场景的模板就能共用同一套填充逻辑。

`compliance_basis` 给出四条字段合规依据（ISO/IEC 17025:2017 §7.8、CNAS-EL-13、
European Accreditation 官方问答、QC/T 626 第 7 章检验规则）。
`conclusion_binding` 说明报告「结论」段不是自由文本，而是由判定结果按检验规则聚合出来的——
**防夹三条按目标市场只取其一参与聚合，不参与的两条标 N/A 而不是 PASS**。

## 六、合成数据说明

**这三条数据是合成的，不是实测。前端展示时必须显式标注「合成，非实测」，
并且不得进入任何合规报告**（`safety-interlocks.json` 的 `SI-PR-05` 把这条写成了流程联锁）。

### 6.1 模型

一阶有刷直流电机电气-机械耦合模型，与 gym-electric-motor
（德国帕德博恩大学电驱动系统教研室，MIT 许可，https://github.com/upb-lea/gym-electric-motor）
所用的直流电机模型同型，但本包**不引入该依赖**，直接在 `_build/gen_waveforms.py` 里用
显式欧拉积分实现，便于逐行审阅：

```
L·di/dt = U·duty − R·i − Ke·ω
J·dω/dt = Kt·i − B·ω − T_load
dx/dt   = k_arm·ω                  （旋转 → 玻璃托架直线位移）
F_out   = Kt·i·η / k_arm_m         （η 为蜗杆传动机械效率）
```

参数：`U = 13.5 V`、`R = 0.52 Ω`、`L = 0.80 mH`、`Ke = Kt = 0.020`、`J = 2.0e−5 kg·m²`、
`B = 2.0e−6`、`k_arm = 0.226 mm/rad`、`η = 0.105`、每转纹波 8 个、纹波深度 6 %。

### 6.2 标定口径

参数是标定到让稳态量落在 QC/T 626-2019 征求意见稿给的量级上的：

| 量 | 合成值 | 判据 |
| --- | --- | --- |
| 堵转电流 | ≈ 27.4 A（峰值，含纹波） | 5.4.1 b) 不大于 28 A |
| 上升速度 | ≈ 118 mm/s | 5.4.1 d) 80 至 160 mm/s |
| 堵转力 | ≈ 254 N | 5.4.1 c) 不小于 212 N |
| 夹持力峰值（防夹条） | ≈ 42 N | GB 11552-2009 §4.8.3.1.1 不超过 100 N |

**这是「让示例数据看起来合理」的标定，不是任何真实产品的参数辨识结果。**

### 6.3 采样

内部按 20 kHz 积分，箱式平均降采样到 2 000 Sa/s 输出，24 000 行 = 12.0 s。
降采样等效于一阶抗混叠，因此输出里的换向纹波已被大幅衰减——
**2 kHz 只够看电流包络，不够做纹波计数测速**（纹波基频在本模型下约 600 至 700 Hz）。
`ripple_pulse` 列在这个采样率下已严重欠采样，仅作示意。

采样率与行数刻意与第一个包的示波器深存储导出口径（2 000 Sa/s、24 000 行）对齐，
好让前端的时序组件不用改。

### 6.4 三条工况

| 文件 | 工况 | 设计意图 |
| --- | --- | --- |
| `normal-up-down-cycle.csv` | 怠速 → 上升 3.5 s → 上止点堵转 1 s → 断电停 4 s → 下降 | 时间轴照征求意见稿 6.9.1 注 3 的耐久单循环波形排。喂给 WR-WF-001 与 WR-WF-004 回放 |
| `antipinch-trigger.csv` | 上升途中在开口 170 mm 处遇障 → 电流突增 → 检出 → 回缩 60 mm | 障碍物用刚度 10 N/mm 的半刚性试验棒建模（GB 11552-2009 §4.8.3.1.3 的测量工具刚度），夹持力 = 刚度 × 侵入量。`pinch_force_n` 列是给 TR-PINCH-01 判据直接取数用的 |
| `stall-saturation.csv` | 上升到上止点后持续加压 5.3 s，电流爬到 U/R 饱和平台 | **刻意不启用堵转保护**，目的是录出完整的饱和平台，用来标定 `stall_current_threshold`（默认 24 A）与 `stall_debounce_time` |

`phase` 列给出工况标记，防夹条的五相是
`UP → PINCH_CONTACT → PINCH_DETECTED → RETRACT → RETRACT_DONE`。
