# OmniTest 视觉设计系统 v2

适用范围：`~/agent-test-web`（多场景 Agent 测试系统网页原型）的全部六条流程页面。
本轮只做视觉与版式，数据逻辑（场景包加载、`evaluate` 判定、工作流解析）一律不动。

样板页：流程 4「启动测试及结果分析」，默认场景包 `motor.cooling-fan.fortior-fu6832`（峰岹散热风扇 FU6832 驱动板）。
其余五页按本文第 6 节铺开。

## 1. 基准画布与栅格

| 项 | 值 |
| --- | --- |
| 基准画布 | 1920 × 1080（16:9） |
| 顶栏 | 高 64，通栏贴顶 |
| 动作条 | 高 48，次表面浅绿 |
| 内容区外边距 | `clamp(16px, 1.7vw, 32px)`，1920 下即 32 |
| 三块间距 | `clamp(14px, 1.25vw, 24px)`，1920 下即 24 |
| 左栏「参数」 | `minmax(300px, 380px)` |
| 右列行高 | `1.75fr : 1fr`（面板 : 副驾），不写死像素 |
| 右侧工具条 | 固定 56 |
| 卡片间距 | `clamp(12px, 0.9vw, 16px)` |

**1440 / 1600 不破版的做法**：所有外边距、间距、面板内边距都用 `clamp()` 随视口收缩；右列两行用 `fr` 比例（面板 : 副驾 = 1.75 : 1）而非固定高度；卡片网格用 `minmax(0, 1fr)`。因此缩小视口只会让留白变窄、卡变矮，不会把卡裁在视口外。**禁止**在布局里写死 `height: 336px` 这类绝对高度。

所有卡边缘落在 8pt 栅格上（间距 8/12/16/24/32，卡内 padding 12/20/24）。

## 2. 色彩

主色为中大墨绿 `#2E5E45`，按 HSL 均匀推 10 档（`--p-50` … `--p-900`，`#2E5E45` = `--p-700`）。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--p-700` | `#2E5E45` | 品牌主色：主按钮、当前步、图标 |
| `--p-600` / `--p-800` | 主色 ±明度 | 渐变端点、hover |
| `--p-50` / `--p-100` | 极浅绿 | 次表面、分段控件槽、图标底 |
| `--p-200` / `--p-300` | 浅绿 | 次表面描边、滚动条 |
| `--tp-bg` | `#F6F8F6` | 页面底（冷白偏绿） |
| `--tp-surface` | `#FFFFFF` | 主表面 |
| `--tp-line` / `--tp-line-soft` | `#E3E8E4` / `#EEF2EF` | 边框 / 卡内分隔线 |
| 文字 | `#1F2A24` / `#5B6B62` / `#9AA69F` | 主 / 次 / 弱 |

**状态色只三档，用得极克制**：成功 = 主色 `--p-600`；警告 = 低饱和琥珀 `#B7791F`（待确认、闸门未放行）；危险 = 暗红 `#A6353A`（判不通过、急停、丢弃）。**每屏状态色出现处 ≤ 5**。

**渐变只有一处口径**：`--tp-grad`（600→700→800，140°），只给品牌 logo 方块、当前步圆点、主按钮、发送按钮。其余一律禁渐变。

## 3. 三级表面

层次靠"表面等级"分，不靠给每个框都描一样的边。

| 级别 | 做法 | 用在哪 |
| --- | --- | --- |
| 一级 · 主表面 `.surface-1` | 白底 + 圆角 12 + 柔阴影 `0 1px 2px / 0 8px 24px rgba(31,42,36,.06)` | 左栏、面板、副驾三块容器 |
| 二级 · 次表面 `.surface-2` | `--p-50` 浅绿底、圆角 10、**无阴影** | 动作条、工具条底、放大浮层内衬、分段控件槽 |
| 三级 · 行级 | 无框，只有 `border-bottom: 1px solid --tp-line-soft` | 参数行、判定行、闸门行、日志行 |

**每页只有 1 个视觉主体（hero）**：网格首卡横跨两格，卡头图标反白实底、卡框带 `--p-200` 描边与柔阴影；其余卡默认极淡阴影，hover 才升起。

## 4. 字体与文案密度

- 正文 `Inter Variable` + `Noto Sans SC`；等宽 `IBM Plex Mono`（只给日志、终端、原始 JSON）。
- 数字全局 `tabular-nums`（`body` 上已开），大号数值用 `.num` + `font-semibold`。
- 字阶：12 / 13 / 14 / 16 / 20 / 26。**最小 12px**，不再有 10px、11px。
- 标签 12px 灰、`font-medium`；值 15–17px 深色；卡标题 14px semibold；区标题 16px semibold；大数字 26px。

**文案纪律（本轮整改的重点）**：

1. 任何标签 ≤ 6 字。长参数名用 `short(name)` 截断，全名 + 代号 + 取值范围 + 来源进 `Tooltip`。
2. 整句话只允许出现在两个地方：`Tooltip` / `InfoTip` 的气泡里，和副驾的对话气泡里。卡面、参数行、状态行一律只留关键词。
3. 来源不写字，用 `SourceTag` 的小圆点色标（文档 = 深绿、人工 = 琥珀、建议 = 浅绿），悬停出全称。
4. 一屏之内同一条信息不说第二遍（旧版把置灰理由同时写在动作条、左栏底部、闸门条三处，现在只留按钮的 tooltip）。

## 6. 版式规则与六页铺法

### 应用壳（`src/app/`）

- **顶栏 64**：左品牌（渐变墨绿方块 + OmniTest 字标）；中六流程 stepper（圆形序号 / 当前步换流程图标反白 / 已确认打勾，短名 ≤6 字，步间细连线）；右场景包芯片（`ProductCascader`，点开才出三级级联）+ 台架状态点 + 联锁数 + 头像。
- **动作条 48**：浅绿次表面。左 3–4 个带图标按钮，每页只有 1 个 `primary`；置灰按钮的理由只挂 tooltip。右一句状态 ≤12 字。
- **左栏 380**：`PanelHeader` → 分组 `Collapsible`（图标 + 短标题 + 计数）→ 参数行（来源圆点 + 标签 ≤6 字 + 值大字 + 单位 + 圆形加减）→ 底部 `border-t` + 半透明白底悬浮主按钮。
- **右上面板**：`PanelHeader` + `Segmented`（网格 / 画布）；网格是 3 列 × 2 行，首卡 hero 横跨两格；右侧 56 工具条按四组分段，组间分隔线 + 留白，按钮 34×34 白底描边、右上角状态小圆点，悬停出名称。
- **右下副驾**：头像 + 名称 + 状态徽标；副驾气泡左（白底描边，左下角收尖）、人右（浅绿底）；工具调用与判定压成紧凑卡（图标点 + 一行 + 徽标 + 展开）；输入框圆角 12，右侧麦克风与发送（渐变药丸）；下方一行模型 + 权限 `Segmented` + 只读免确认开关，整句约束收进开关 title。

### 各页 hero 与卡片组合

| 流程 | hero（首卡，横跨两格） | 第 2 槽（右上） | 第二行三张 | 左栏分组 |
| --- | --- | --- | --- | --- |
| 1 知识库管理 | 文档库 / 工程树 | 知识库依据 | 转化进度 · 历史对比 · 工具清单 | 文档分类 / 转化设置 / 索引 |
| 2 初始化配置 | 产品示意图（真图铺满） | 原理图 | 工程树 · 安全联锁 · 台架实况 | 本体属性 8 组（走壳层默认左栏） |
| 3 测试需求确认 | 工作流画布 | 原理图 | 判定表 · 知识库依据 · 历史对比 | 判据分组 / 工作流参数 |
| **4 启动测试**（样板） | **时序曲线** | 原理图 | 判定卡 · 安全联锁环 · 单机设备会话 | 控制参数分组 / 运行设置 / 安全闸门 |
| 5 调优确认及运行 | 历史波形叠加对照 | 时序曲线 | 候选参数队列 · 知识库依据 · 判定卡 | 可调参数（F5）/ 候选对照 |
| 6 测试报告及产出 | 报告预览 | 产物留档 | 判定汇总 · 历史对比 · 模板字段 | 报告模板 / 字段补全 |

铺页时**只改视觉，不改数据来源**：卡片实现仍在 `src/features/flow-*/panel.tsx`，通过 `src/features/index.tsx` 的 `CARD_IMPL` 分派；卡槽顺序即视觉权重，在 `src/data/loadScene.ts` 各 `*Flow()` 的 `cards: [...]` 里排——**第一张就是 hero**。纯文字的卡（执行进度与日志一类）排到第 6 位以后，从卡头「换卡」进得来即可，不占卡槽。

铺页三条硬约束：

1. 每页只有一个 hero，其余卡不加阴影强调。
2. 每张卡的卡头必须给图标（`CARD_ICON`），卡体优先放图（曲线、图纸、画布、环形进度、大数字），不要放段落。
3. 卡内长列表用 `mask-image` 底部渐隐 + `no-scrollbar`，不要把半行硬切在卡底。

## 7. 动效

只在三处：进场（`animate-rise`，卡片按 45ms 步进错峰）、hover（卡片升起 1px + 阴影、按钮 `active:translate-y-px`）、状态变化（环形进度 `stroke-dasharray` 0.4s、进度条宽度 0.5s）。曲线与画布不加动效。

## 10. 收尾变更记录（六页铺完之后）

六条流程页由六个 agent 并行铺完之后做的一轮收口。并行期各页 agent 不动共享文件，
遗留下来的跨页改动与六页一致性问题在这一轮一次性处理。

### 10.1 卡片正名

四张卡此前借用别的卡片库标识显示，卡名与卡里的内容对不上。这一轮给它们各自的
标识，五处登记同步改到位（`src/data/types.ts` 的 `CARD_IDS`、`src/data/cards.ts` 的
`CARD_LIB`、`src/app/icons.ts` 的 `CARD_ICON`、`src/app/CardArt.tsx` 的 `ART`、
`src/features/index.tsx` 的 `CARD_IMPL`），卡槽顺序在 `src/data/loadScene.ts` 各
`*Flow()` 的 `cards: [...]` 里跟着改。

| 新标识 | 卡名 | 出在哪 | 此前借用 |
| --- | --- | --- | --- |
| `wf-lib` | 工作流库 | 流程 3 第 2 槽 | `project-tree`（工程与文件树） |
| `pipeline` | 转化流水线 | 流程 1 第 3 槽 | `progress`（执行进度与日志） |
| `experience` | 经验库 | 流程 1 第 4 槽 | `history`（历史对比） |
| `candidates` | 候选队列 | 流程 5 第 2 槽 | `progress`（执行进度与日志） |

同时取消两处就地注册：流程 1 的「工具清单与状态」（原在 `flow-kb/panel.tsx` 里

现在都走 `CARD_IMPL` 统一分派。流程 5 用 `queueMicrotask` 在模块求值后补登记
`progress` 卡槽的那段绕行代码一并删除——「候选队列」有了自己的标识，不需要再借。

### 10.2 动作条

`src/data/flows.ts` 的四条流程动作按业务口径重排，每条流程仍只有一个 `primary`，
新动作的图标在 `src/app/TopBar.tsx` 的 `ACTION_ICON` 里登记。

| 流程 | 动作（主动作在前） |
| --- | --- |
| 1 知识库管理 | 上传文档 · 新建分类 · 沉淀为经验 · 管理条目 |
| 3 测试需求确认 | 确认需求基线 · 导入标准 · 编辑工作流 · 另存模板 |

### 10.3 副驾

- **首条消息**（`src/features/copilot/scripts.ts`）：六条流程各自的第一句改成从场景包
  取数，一到两句说清本流程的规模与边界，不再是与场景无关的固定句。
- **消息流宽度**（`src/features/copilot/copilot.css`）：`agent-chat` 默认工具卡宽 82%、
  气泡 78%，1920 下副驾右边空出一大片。现在工具卡与判定卡撑满宽度、气泡放宽到
  88%，与本来就满宽的输入框右边缘对齐。

### 10.4 六页一致性

- **左栏底部主按钮**收进 `src/features/shared/bits.tsx` 的 `ConfirmFooter`，六页共用同一
  组件：通栏、`lg`、`primary` 实底渐变、`CheckCircle2` 图标，文案统一
  「确认〈对象〉· 〈数字〉〈量词〉」。此前 6 页有 3 种形态（实底 / 浅绿 / 随状态换色）、
  4 种文案格式；前置条件没满足时也不再换形态、不置灰，理由只挂 tooltip（§4 文案纪律 4）。
  `Tooltip` 的根节点是 `inline-flex`，包着通栏按钮时会把宽度收成内容宽——流程 2 与
