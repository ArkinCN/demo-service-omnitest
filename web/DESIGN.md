# OmniTest 视觉设计系统 v2

适用范围：`c/`（多场景 Agent 测试系统网页原型）的全部六条流程页面。
本轮只做视觉与版式，数据逻辑（场景包加载、`evaluate` 判定、工作流解析）一律不动。

样板页：流程 4「启动测试及结果分析」，默认场景包 `motor.cooling-fan.fortior-fu6832`（峰岹散热风扇 FU6832 驱动板）。
其余五页按本文第 6 节铺开。

## 1. 基准画布与栅格

| 项 | 值 |
| --- | --- |
| 基准画布 | 1920 × 1080（16:9） |
| 顶栏 | 高 64，通栏贴顶 |
| 动作条 | 高 48，次表面浅绿 |
| 内容区外边距 | `clamp(16px, 1.7vw, 32px)`，1920 下即 32 |
| 三块间距 | `clamp(14px, 1.25vw, 24px)`，1920 下即 24 |
| 左栏「参数」 | `minmax(300px, 380px)` |
| 右列行高 | `1.75fr : 1fr`（面板 : 助手），不写死像素 |
| 右侧工具条 | 固定 56 |
| 卡片间距 | `clamp(12px, 0.9vw, 16px)` |

**1440 / 1600 不破版的做法**：所有外边距、间距、面板内边距都用 `clamp()` 随视口收缩；右列两行用 `fr` 比例（面板 : 助手 = 1.75 : 1）而非固定高度；卡片网格用 `minmax(0, 1fr)`。因此缩小视口只会让留白变窄、卡变矮，不会把卡裁在视口外。**禁止**在布局里写死 `height: 336px` 这类绝对高度。

所有卡边缘落在 8pt 栅格上（间距 8/12/16/24/32，卡内 padding 12/20/24）。

## 2. 色彩

主色为中大墨绿 `#2E5E45`，按 HSL 均匀推 10 档（`--p-50` … `--p-900`，`#2E5E45` = `--p-700`）。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--p-700` | `#2E5E45` | 品牌主色：主按钮、当前步、图标 |
| `--p-600` / `--p-800` | 主色 ±明度 | 渐变端点、hover |
| `--p-50` / `--p-100` | 极浅绿 | 次表面、分段控件槽、图标底 |
| `--p-200` / `--p-300` | 浅绿 | 次表面描边、滚动条 |
| `--tp-bg` | `#F6F8F6` | 页面底（冷白偏绿） |
| `--tp-surface` | `#FFFFFF` | 主表面 |
| `--tp-line` / `--tp-line-soft` | `#E3E8E4` / `#EEF2EF` | 边框 / 卡内分隔线 |
| 文字 | `#1F2A24` / `#5B6B62` / `#9AA69F` | 主 / 次 / 弱 |

**状态色只三档，用得极克制**：成功 = 主色 `--p-600`；警告 = 低饱和琥珀 `#B7791F`（待确认、闸门未放行）；危险 = 暗红 `#A6353A`（判不通过、急停、丢弃）。**每屏状态色出现处 ≤ 5**。

**渐变只有一处口径**：`--tp-grad`（600→700→800，140°），只给品牌 logo 方块、当前步圆点、主按钮、发送按钮。其余一律禁渐变。

## 3. 三级表面

层次靠"表面等级"分，不靠给每个框都描一样的边。

| 级别 | 做法 | 用在哪 |
| --- | --- | --- |
| 一级 · 主表面 `.surface-1` | 白底 + 圆角 12 + 柔阴影 `0 1px 2px / 0 8px 24px rgba(31,42,36,.06)` | 左栏、面板、助手三块容器 |
| 二级 · 次表面 `.surface-2` | `--p-50` 浅绿底、圆角 10、**无阴影** | 动作条、工具条底、放大浮层内衬、分段控件槽 |
| 三级 · 行级 | 无框，只有 `border-bottom: 1px solid --tp-line-soft` | 参数行、判定行、闸门行、日志行 |

**每页只有 1 个视觉主体（hero）**：网格首卡横跨两格，卡头图标反白实底、卡框带 `--p-200` 描边与柔阴影；其余卡默认极淡阴影，hover 才升起。

## 4. 字体与文案密度

- 正文 `Inter Variable` + `Noto Sans SC`；等宽 `IBM Plex Mono`（只给日志、终端、原始 JSON）。
- 数字全局 `tabular-nums`（`body` 上已开），大号数值用 `.num` + `font-semibold`。
- 字阶：12 / 13 / 14 / 16 / 20 / 26。**最小 12px**，不再有 10px、11px。
- 标签 12px 灰、`font-medium`；值 15–17px 深色；卡标题 14px semibold；区标题 16px semibold；大数字 26px。

**文案纪律（本轮整改的重点）**：

1. 任何标签 ≤ 6 字。长参数名用 `short(name)` 截断，全名 + 代号 + 取值范围 + 来源进 `Tooltip`。
2. 整句话只允许出现在两个地方：`Tooltip` / `InfoTip` 的气泡里，和助手的对话气泡里。卡面、参数行、状态行一律只留关键词。
3. 来源不写字，用 `SourceTag` 的小圆点色标（文档 = 深绿、人工 = 琥珀、建议 = 浅绿），悬停出全称。
4. 一屏之内同一条信息不说第二遍（旧版把置灰理由同时写在动作条、左栏底部、闸门条三处，现在只留按钮的 tooltip）。

## 6. 版式规则与六页铺法

### 应用壳（`src/app/`）

- **顶栏 64**：左品牌（渐变墨绿方块 + OmniTest 字标）；中六流程 stepper（圆形序号 / 当前步换流程图标反白 / 已确认打勾，短名 ≤6 字，步间细连线）；右场景包芯片（`ProductCascader`，点开才出三级级联）+ 台架状态点 + 联锁数 + 头像。
- **动作条 48**：浅绿次表面。左 3–4 个带图标按钮，每页只有 1 个 `primary`；置灰按钮的理由只挂 tooltip。右一句状态 ≤12 字。
- **左栏 380**：`PanelHeader` → 分组 `Collapsible`（图标 + 短标题 + 计数）→ 参数行（来源圆点 + 标签 ≤6 字 + 值大字 + 单位 + 圆形加减）→ 底部 `border-t` + 半透明白底悬浮主按钮。
- **右上面板**：`PanelHeader` + `Segmented`（网格 / 画布）；网格是 3 列 × 2 行，首卡 hero 横跨两格；右侧 56 工具条按四组分段，组间分隔线 + 留白，按钮 34×34 白底描边、右上角状态小圆点，悬停出名称。
- **右下助手**：头像 + 名称 + 状态徽标；助手气泡左（白底描边，左下角收尖）、人右（浅绿底）；工具调用与判定压成紧凑卡（图标点 + 一行 + 徽标 + 展开）；输入框圆角 12，右侧麦克风与发送（渐变药丸）；下方一行模型 + 权限 `Segmented` + 只读免确认开关，整句约束收进开关 title。

### 各页 hero 与卡片组合

| 流程 | hero（首卡，横跨两格） | 第 2 槽（右上） | 第二行三张 | 左栏分组 |
| --- | --- | --- | --- | --- |
| 1 知识库管理 | 文档库 / 工程树 | 知识库依据 | 转化进度 · 历史对比 · 工具清单 | 文档分类 / 转化设置 / 索引 |
| 2 初始化配置 | 图纸铺满（卡名随图取：原理图 / 结构示意图） | 文档读取 | 工程树 · 安全联锁 · 台架实况 | 本体属性 8 组（走壳层默认左栏） |
| 3 测试需求确认 | 工作流画布 | 原理图 | 判定表 · 知识库依据 · 历史对比 | 判据分组 / 工作流参数 |
| **4 启动测试**（样板） | **时序曲线** | 原理图 | 判定卡 · 安全联锁环 · 单机设备会话 | 控制参数分组 / 运行设置 / 安全闸门 |
| 5 调优确认及运行 | 历次波形叠加对照（PASS 主色 + 两档次级绿） | 候选队列 | 知识库依据 · 判定卡 · 参数变更 | 可调参数（F5）/ 候选对照 |
| 6 测试报告及产出 | 报告预览 | 产物留档 | 判定汇总 · 历史对比 · 模板字段 | 报告模板 / 字段补全 |

铺页时**只改视觉，不改数据来源**：卡片实现仍在 `src/features/flow-*/panel.tsx`，通过 `src/features/index.tsx` 的 `CARD_IMPL` 分派；卡槽顺序即视觉权重，在 `src/data/loadScene.ts` 各 `*Flow()` 的 `cards: [...]` 里排——**第一张就是 hero**。纯文字的卡（执行进度与日志一类）排到第 6 位以后，从卡头「换卡」进得来即可，不占卡槽。

铺页三条硬约束：

1. 每页只有一个 hero，其余卡不加阴影强调。
2. 每张卡的卡头必须给图标（`CARD_ICON`），卡体优先放图（曲线、图纸、画布、环形进度、大数字），不要放段落。
3. 卡内长列表用 `mask-image` 底部渐隐 + `no-scrollbar`，不要把半行硬切在卡底。

## 7. 动效

只在三处：进场（`animate-rise`，卡片按 45ms 步进错峰）、hover（卡片升起 1px + 阴影、按钮 `active:translate-y-px`）、状态变化（环形进度 `stroke-dasharray` 0.4s、进度条宽度 0.5s）。曲线与画布不加动效。

## 10. 收尾变更记录（六页铺完之后）

六条流程页由六个 agent 并行铺完之后做的一轮收口。并行期各页 agent 不动共享文件，
遗留下来的跨页改动与六页一致性问题在这一轮一次性处理。

### 10.1 卡片正名

四张卡此前借用别的卡片库标识显示，卡名与卡里的内容对不上。这一轮给它们各自的
标识，五处登记同步改到位（`src/data/types.ts` 的 `CARD_IDS`、`src/data/cards.ts` 的
`CARD_LIB`、`src/app/icons.ts` 的 `CARD_ICON`、`src/app/CardArt.tsx` 的 `ART`、
`src/features/index.tsx` 的 `CARD_IMPL`），卡槽顺序在 `src/data/loadScene.ts` 各
`*Flow()` 的 `cards: [...]` 里跟着改。

| 新标识 | 卡名 | 出在哪 | 此前借用 |
| --- | --- | --- | --- |
| `wf-lib` | 工作流库 | 流程 3 第 2 槽 | `project-tree`（工程与文件树） |
| `pipeline` | 转化流水线 | 流程 1 第 3 槽 | `progress`（执行进度与日志） |
| `experience` | 经验库 | 流程 1 第 4 槽 | `history`（历史对比） |

## 11. 第三轮 · C 区统一画板（W3 追加）

C 区从 3×2 卡片网格改成一块可滚轮缩放的统一画板，网格降为备选视图。画板本体在
`src/features/canvas/`，用的是工程里已有的 React Flow（`@xyflow/react` 12.11.6），
不自研 SVG；原来 `src/app/ResourcePanel.tsx` 里那套绝对定位加手画连线的 `CanvasView` 整个下架。

**外框与缩放。** C 区容器尺寸与位置完全不变，只有画布内容随滚轮以指针为锚点缩放，
范围 0.4× 至 2.5×。左下角一条缩放条（− / 百分比 / + / 复位），右下角的缩略导航图
只在内容超出视口时出现。实测：1920×1080 下画板外框 1396×516，缩到 63% 时外框仍是
1396×516（`scripts/shootw3.mjs` 打印的原始数字）。

**节点。** 十一类，分五组，组内不超过 5 项——被测对象（产品、原理图）、测量设备
（示波器、台架）、激励与环境（程控电源）、过程与数据（工作流、曲线、判定）、
服务与连接（设备 MCP、联锁、知识）。节点本体就是一张 `PanelCard`：卡头 38、图标徽章、
14px 卡名、放大按钮，卡体是 `CardArt` 线条稿或三行事实，卡底一行连接态。画板不另起
一套卡片样式。

**边。** 两种语义、两种线型：物理接线是墨绿实线 1.5，边上标通道名；数据流是浅绿虚线
`6 4`、线宽 1。通道名取 `src/data/bench.ts` 的 `channelLabel()`，标注里一律带
「待客户确认」——那套映射还没经客户书面确认。边不参与任何计算。

**状态色的取舍。** 工具条的三态描边与节点的连接态点，在线态用的是品牌绿阶
（`--p-300` / `--p-400`）而不是成功状态色 `--p-600`，暗红只留给异常。理由是一条 14 枚
图标的工具条如果把在线态画成饱和绿，一屏状态色会直接超过第 8 节「每屏 ≤5 处」的上限。

**右侧工具条 56。** 顶部单独一枚刷新；其下按能力域分组，每组带两字组名与分隔线，
全称进 tooltip；每枚工具块可拖进画板，落点即建节点，落点之外放手取消。

**版式与默认视图。** 人摆过的版式按「场景包 × 流程」存 localStorage；每条流程的默认
视图读场景包 `scene.json` 的 `default_view` 段（初始化与需求确认走画板，启动测试、
调优、报告走网格），不写死在代码里。

## 12. 第三轮收尾（W6 追加）

前五包并行落完之后的一次统一收口。只记与视觉、版式、口径有关的改动，接口清单在 `README.md`。

**画板控件换角。** 缩放条从左下角移到**右下角**，与客户参考页
（`_调研/ref-客户Copilot页面-用户提供-20260919.png`）一致；缩略导航图让到**左下角**，
两个控件仍分处两角、互不遮挡。缩略导航图的描边由最浅的 `--tp-line` 提到 `--p-200`，
遮罩由浅绿实底改成 10% 墨绿——它浮在带点阵的画板底上，用最浅那档看不出这是一个控件。
节点的交互口径保持 W3 定的那套：单击选中、双击或点卡头放大按钮展开。

**网格不再回填。** C 区网格视图以场景包的 `content.cards` 为准，有几张铺几张
（`slotStyle()` 本来就支持 3 / 4 / 5 三种版式），不再拿「注册过但没进卡槽」的卡补满五格。
直接后果是第三轮删掉的三张卡真正从屏幕上消失：流程 3 的「原理图」「安全联锁状态盘」、
流程 4 的「判定卡」。没进卡槽的卡仍可取用，入口在卡头的「换卡」下拉里。
「单机设备会话」这张独立卡连同卡槽一并撤掉，设备只以画板上的 MCP 节点出现。

**滚动条要看得见。** 两处一起改：一、`.fade-b` 的底部渐隐由 `mask-image` 改成一层
`position: sticky` 的 `::after` 覆盖层——遮罩会连带把容器自己的滚动条一起淡掉，
换成覆盖层之后滚动条不再受影响；二、滚动条轨道给 `--p-50` 浅绿底、滑块加深到 `--p-300`、
悬停 `--p-400`，并给滚动容器留 `scrollbar-gutter: stable` 的固定水槽。留水槽是必须的：
不留的话 Chromium 走覆盖式滚动条，不滚的时候一个像素都不画。标准属性
`scrollbar-color` / `scrollbar-width` 关在 Firefox 专属的 `@supports` 里，
因为 Chromium 一看到它们就整套忽略 `::-webkit-scrollbar` 规则。

**助手按钮条的忙态。** 一轮没跑完时只禁用**执行类**按钮，讲解与准备类保持可点。
原先整条随忙态置灰，于是流程 3 那种「开场脚本停在启动闸门上、整轮不结束」的页面
会五枚全灰，观感像坏掉了；真正不能并发的只是会动设备与数据的执行类。

**助手按钮条的挂位。** 由并行期的「往 `.ac-root` 里 portal 一个宿主节点」改成
`AgentChat` 的正经插槽 `actionSlot`（渲染在 `.ac-stream` 与 `.ac-composer` 之间的
`.ac-slot` 里）。样式选择器随之从 `.copilot-slot` 挂到 `.ac-slot`，好让
`/knowledge` 这种不套 `FlowCopilot` 的页面直接用同一套外观。知识库页的助手栏
展开高度相应加 72px，不然开场白会被按钮条硬切在半行上。

**图标补齐。** 助手动作图标表由 17 个扩到 28 个，补的 11 个是
`library` `folder-tree` `scale` `link` `workflow` `lock` `stethoscope` `network`
`file-diff` `note-pen` `package`。并行期只有 17 个可用、29 枚按钮被迫共用，
语义有折损；补齐后场景包 `copilot-actions.json` 里这 11 枚按 `icon_draft` 记的原语义回填。
同一条流程内仍然不重样。

**顶栏多一枚分段控件。** 「演示 / 全量」，切的是 `useAppStore.demoMode`。
两边读的是同一份场景包：演示只露 `demo_profile` 点名的那几项，全量把登记过的全表摊开，
不删任何数据。人工选择持久到 localStorage；地址栏 `?mode=full` 仍然强制全量。

**空态不许被读成通过。** 调优页「未达标项」的空态由「本轮无不通过项」改为
**「本轮无现场实测，判据未求值」**，并写明判据要的现场实测量本轮一条都没采，
因此既判不出通过也判不出不通过，屏幕上的时序与候选是既有数据的回放。
0 条不通过不是「都合格」，这句话必须写在屏幕上。

**全工程一律称「助手」。** 第二轮对助手的旧称在 `src/` 与 `public/` 下已零命中。
汽车场景包里的「副驾驶门」是车门位置、不是助手旧称，按 W2 的处置改成
「前排乘客门与后门」并保持——那是 VW 80000 的 M-06 按门位分档的试验条件，
